# Minimal startup reentry repair proposal (not implemented)

The actual old-source run `before-fix-001` completed initial build and a fresh-process repeat, then a real R/F publication exchanged the Workspace inode and committed R revision 2. HostFiles independently resolves the new registered root and F version. Reentry fails in two places: `StartupAssets.__init__` regenerates host.initial_sources with the current inode and immutable host.json rejects it; the retained object's build rejects the now-legitimate inode as STALE_BINDING. Neither failure is a missing Engine dependency.

Keep ownership with the existing records:

- On reentry, read and validate the original startup-inputs.json and host.json against the exact fixed supplied configuration; do not replace the saved initial source identity with today's inode. Retain fixed paths, resource IDs, namespace, trusted roots, code/dependency/profile refs. Loading these original bytes is preparation only, not authorization to use a changed live resource.
- Read the original F capture result using its already deterministic startup request ID derived from the saved initial binding. Validate the original journal request, complete result, Git bundle and capture provenance before returning the original version. Do not recapture the new Workspace under the old initial request or silently change initial_refs. The same actual historical Harness/capability descriptors and registration specs remain returned.
- Before accepting a changed caller root, consult the existing actual ControlStore and F installation records. Bootstrap already has both before build; a narrow `build(files, control=control)` or equivalent trusted injected checker is sufficient. An original R registration by itself must agree with current path/dev/ino/revision. Its corresponding confirmed installation must bind the old/staged roots, base/output versions and original resource; actual F query/layout and current complete tree must match. Pending/conflicting/missing evidence remains explicit and cannot reset registration or claim recovery. Use existing R/F records, not a new current-version catalog.
- If no legitimate R/F installation explains a change, retain SA02's existing rejection for replacement and ordinary edits. Before registration or before the first completed capture, only the unchanged original source is eligible for initial capture. Exact supplied config/ref changes remain conflicts.
- Bootstrap may continue to expose the original initial_refs for initial submission. Restoring accepted invocations uses their original R/E/F/S references, and HostFiles already resolves the currently registered resource when given its actual F version. Do not mutate old invocation inputs or rewrite an old historical reference to mean the current path.

This is one startup-loading seam. No product code, new state machine, independent index, Engine restart, task replay or M03/M04 success is proposed or claimed. The fresh-process probe must continue to return identical original initial refs after the actual authorized install and preserve the old inode/archive. Original SA02 unauthorized replacement behavior must remain covered when the repair is independently checked.
