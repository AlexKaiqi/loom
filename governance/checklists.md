# 执行与验收检查表

使用方式：只复制当前阶段适用条目到工作记录。勾选必须附证据引用、被验范围/版本和裁定；空勾选或“已检查”文字不能算通过。无需每次小修改重填全表。

记录格式：条目 ID | PASS / FAIL / UNVERIFIED / BLOCKED / INVALIDATED / N/A | 证据引用 | 范围与版本 | 裁定理由。N/A 需原始范围依据，不能豁免必须项。

## 启动与恢复

- [ ] R01 已核对用户原始目标、当前授权、v5 和最近恢复记录；冲突、未知项有去向。
- [ ] R02 当前阶段及未过门槛明确；没有把摘要中的“完成”当作验收证据。
- [ ] R03 实际文件、依赖、契约和数据变化已核对，相关旧证据已失效或有复用理由。
- [ ] R04 未决执行已按身份查询；下一步关联一项目标、性质或阻塞，并有预期证据。

## 恢复后的工作收敛检查

只用于当前工作单元，不新增阶段；依据[暂停复盘](pause-review-2026-09-13.md)。

- [ ] P01 已确认用户允许恢复；本轮文档完成或自动续跑未被误当继续授权。
- [ ] P02 下一项工作能明确解除原 Runtime/M01 的具体缺口；使用的成熟能力、必要自研差异及先行用例明确。
- [ ] P03 新增能力先独立验证再装配；既有有效证据按影响复用，没有重复建设验证平台或偷偷跳过原必须项。
- [ ] P04 原失败、用户中断、未执行项分别记录；固定响应、真实模型、组件与系统结论未混淆。
- [ ] P05 汇报指出可运行入口与尚缺路径；原完整目标和最终判据未被下一里程碑替代。

## G0 目标基线

- [ ] A01 原始要求逐项编号，区分目标、原则、不变量、候选工程决策和未知项。
- [ ] A02 范围、非目标、优先级和必须项明确；当前阶段成功与整体成功分别定义。
- [ ] A03 每项核心性质有适用边界与可观察判据草案；待定阈值显式保留，不从实现结果倒推。
- [ ] A04 范围分期没有删掉最终必须项；未经授权的目标改变没有混入基线。

## G1 顶层抽象、论证与模拟

- [ ] B01 Runtime、Harness、Surface、Workspace、Session、事件和任务环境的职责与权威状态归属明确。
- [ ] B02 分层、依赖方向、契约、权限与恢复范围明确，备选路线和取舍有依据。
- [ ] B03 模拟前已有待检验性质与判据；正常、边界和关键失败场景有模型或推演结果。
- [ ] B04 核心假设被直接验证或有支持；延期未知项有不影响当前门槛的理由及验证安排。
- [ ] B05 已检查反例与模型现实差距；文档写完、图画完未被当作论证成立。

## G2 定向调研

- [ ] C01 调研问题映射到系统性质，克隆来源和固定提交明确；候选身份未被伪称为确定。
- [ ] C02 声明、源码、运行证据和推断分开；逐项目交付符合原调研清单，未运行实验保持未完成。
- [ ] C03 复用机制、模块位置、前提、限制和适配缺口明确；采用或否决理由可追溯。
- [ ] C04 拟复用代码与依赖的使用条件已核查；更多项目由明确证据缺口驱动。
- [ ] C05 组件拆分能独立验证；关键路线已有足够比较依据，研究收敛不靠跳过必须项。

## G3 组件开发前

- [ ] D01 每个组件有职责、输入输出、状态、依赖、失败语义与版本化契约。
- [ ] D02 性质、通过标准、独立预期和用例早于对应实现保存；验证环境实际可运行。
- [ ] D03 关键验证器能拒绝相关已知错误或缺失能力；断言、用例发现和失败传播有效。
- [ ] D04 替身范围与所需真实依赖明确；不能用替身实验覆盖真实隔离或恢复承诺。
- [ ] D05 正式验证范围、数值阈值和采样方案（适用时）先行；探索测量与正式验收分批，探索结果未被事后设成及格线。

## G4 独立组件验证

- [ ] E01 组件无需完整系统即可按契约验证；实际结果及相关失败场景证据齐全。
- [ ] E02 必须项通过，重要失败修复且相关回归通过；旧失败保留。
- [ ] E03 结构审查覆盖分层、变化隔离、文件复杂度、依赖方向和权威状态归属。
- [ ] E04 实现、判据、fixture 或环境变更有依据和影响分析；没有弱化标准制造成功。
- [ ] E05 当前组件证据有效且可复现；未经独立验证的能力没有进入系统组合。

## G5 组合与系统验证

- [ ] F01 进入组合的组件均有有效通过证据；集成配置变化导致的影响已重新验证。
- [ ] F02 契约语义、真实依赖、输入输出引用及失败传播经过组合验证。
- [ ] F03 从原始任务输入到实际产物的端到端验证通过；Agent 自述不是判据。
- [ ] F04 隔离、恢复、等待期资源、多策略等本阶段必须性质有匹配范围的直接证据。
- [ ] F05 模拟、固定响应、真实模型、组件实验与系统实验分开标注，没有扩大结论。

## 终验：最终独立验收

- [ ] Z01 原始目标—性质—契约—用例—实现—证据完整关联，约定范围全部必须项通过。
- [ ] Z02 验收从原始契约出发，直接检查关键产物和原始记录，并留下独立复跑结果；可用独立角色已启用，角色限制与契约要求如实记录。
- [ ] Z03 判据来源独立、验证可反驳、真实依赖与结论范围相符；不存在空跑、隐瞒跳过或同源自证。
- [ ] Z04 组件、组合和系统的证据职责完整，阶段通过没有被包装成整体完成。
- [ ] Z05 交付快照、测试、数据、相关依赖和配置与证据一致；所有复用有适用依据。
- [ ] Z06 重要失败和验收异议有证据解决；失败、阻塞、未验证和失效项未计入必须项通过。
- [ ] Z07 标准、范围和用例的修改均有独立理由与历史；未通过缩小目标或降低门槛达成完成。
- [ ] Z08 交付可复现，启动/验证/恢复方式与实际一致；限制明确且不遮盖原始必须项缺口。
- [ ] Z09 最终结论明确区分本轮、阶段和全系统范围；所有约定条件满足后停止，不追加无关优化。

## 红旗出现时立即复查

- [ ] X01 是否出现“先把骨架写出来”“先接进去再测”，但上层或组件门槛尚未通过？
- [ ] X02 是否因困难、时间或预算不足，删用例、放宽误差、改预期、减少真实依赖或降低范围？
- [ ] X03 是否用报告、截图、退出码或子 Agent 的总结代替原始证据？
- [ ] X04 是否复用旧版本结果、覆盖失败记录、只保留最好一次，或忽略未运行与跳过？
- [ ] X05 是否绕过顶层矛盾加底层补丁，或用附加功能与文档数量抵消核心要求缺口？
- [ ] X06 是否反复重试而没有新诊断，或在门槛已通过后无理由扩大测试和调研？
- [ ] X07 是否只完成一个里程碑便结束整项授权任务，或因局部阻塞停止无依赖的已授权分支？

红旗条目用于提出问题，不应勾选为通过项。发现任一实际问题，记录受影响性质，暂停相关跨层推进，补证据或修复；不必停止无依赖的已授权工作。
