## 2. 调研范围与完成口径

### 2.1 主清单必须准确保留 12 个项目

主清单身份由 R:10 明确；研究问题来自 R:24–56。下表不表示仓库描述当前仍然成立，身份/重定向/版本须到 G2 核实。

### 2.2 三个身份未定候选不能消失，也不能自动扩成三项全面研究

- OpenMausBot：交互与本地/远端分工（R:64）。
- Rakazo：服务器连续性、状态与沙箱生命周期、可替换后端（R:65）。
- OpenBot：agent 接入中立性、人机接管、运行历史及协议依赖（R:66）。

原项目身份未知已由 R:12、60、68 明确，**不阻塞 G0，也不能虚称已确认；候选不是三个必须全部深入的主项目**。G2 为各候选保留身份与去向记录，依原问题选择需要验证的机制；选择深入、暂缓或不采用应有依据。进入正式研究/复用的候选沿用相关的四类交付口径，不因建议查看顺序冒充质量排名。

### 2.3 NATS 是已有专项，Daytona 是受限历史参考

- **NATS JetStream** 单列为已有事件底座专项，不计入 12 主项目，也不能因“不在主清单”遗漏。需要覆盖命名空间/授权、提交确认、历史读取/回放、消费位置/重复交付、保留、文件视图注入、薄入口校验与管理能力隔离（R:14、74、89；V:129–155）。正式调研按 R:95 保留四类交付，实验验证相关事件机制；研究候选不等于预先采用或接受默认配置。
- **Daytona** 只使用选定历史公开版本中可见的环境创建、隔离、持久文件和生命周期设计，不归入持续跟踪开源底座的首选，不把当前商业能力算入公开实现（R:14、75）。G0 应明确“历史参考”去向；不能为凑数归入主 12，也不能删除该参考。若实际进入代码机制研究/复用，R:95 的相关实验和模块证据仍需记录；若只做历史结构对照，应明确限定结论与未运行部分，不能凭“历史参考”将运行性质判为通过。原文没有要求它接受当前商业平台的全量验证。
- Git、OCI、Linux 文档等是专题依据，不因被引用自动变成新的必须深入项目（R:77）。G2 的收敛以既定交付、比较与证据缺口为依据，不能无止境扩张目录。

## 4. M 不能替代 X 的验收核对标准

| 层次 | 最简范围能说明什么 | 仍须保留的最终义务 |
| --- | --- | --- |
| 正常闭环 | 一个 Surface/Workspace，模板与 blocks 实际投影，两套环境生成报告/更新 notes，事件提交读回；固定响应与真实模型分别验收。 | 不能据单一数字样例或一次模型成功宣称通用任务、所有 Harness 和规模成立。V:216、302–304、324。 |
| 安全与恢复 | 在声明故障范围内，越权、伪造身份、FD 泄漏、重复请求、回执丢失、执行中断，以及保存后释放再恢复有对应证据。 | M 采用的受限范围必须显式保留；未覆盖边界不能被“能重启”吞掉。V:326、332–336。 |
| 多 Surface | 不作为首个样例的前提。 | X 必须加入普通代码定义的等待与信息传递、条件提前发生、无任务进程等待、重启唤起及相关交付责任。V:328；G:30、38。 |
| 多策略 | 最简 Harness 可以是单一参考策略。 | X 必须验证不同策略在同一底座契约上的共存/替换与对照，固定必要输入，隔离可写资源和外部副作用。V:18、108、328；R:56。 |
| 规模 | 单任务正确与等待后释放仅支持相应个体性质。 | X 分别验证等待任务驻留规模与活跃吞吐，并先确定有依据的工作负载、资源/容量/延迟/成本判据。V:99、328、347；G:30。 |
| 完成交付 | 一个组件或里程碑可以独立通过。 | 完整原始要求覆盖、调研交付、设计/判断资产、有效版本证据、必要运行与恢复说明、独立终验都须完成。G:49、53–68。 |

根 Agent 汇总后应逐项核对：

1. 每项 X 原始必须项都有唯一去向；可以跨 M 分期，但不因此改成 optional、N/A 或“后续再说”。
2. X 的正式判据在对应开发/正式实验前准备；待定义不是已通过，也不是自动豁免。
3. M 的通过证据只映射到实际验证的环境、输入、故障和性质；不得将空白 X 项继承为绿色。
4. 发现新反例先分类为既有要求遗漏、当前缺陷或范围外改进，不能以 M 收敛为由拒绝前两类，也不能无限引入第三类。
5. M 完成后自动继续下一已授权阶段；只有 G:66 的完整门槛满足才报告目标完成。当前 G0 文档产出不证明任何 Runtime 运行性质。
