# G3 组件合同与用例准备协调基线

状态：DRAFT，前提 G2 gate PASS / Git 9b6ec8b。无产品组件开始；D01—D05 每组件就绪后才进入对应 G4，组件 E01—E05 通过后才组合。原 244 要求与 M+X 不变。

## 分层和语言选择

R/E/X/F 以 Python 3.10 普通库及标准库 SQLite、现有 nats-py、外部 Docker/Git 接口为优先路线。S 复用固定 Node/Pi 原局部 Session，通过短命子进程的 JSON 管道与受控宿主交接；这是内部组件接口，不是模型可见 DSL。外部 Harness 是普通代码，Runtime 不导入任何参考策略、模板或业务成功判断。V 位于产品外。Python 的相关实际运行库和 SQLite 已有研究许可材料；最终入口发生变化时在使用前核增量。

理由：R/E/X/F 的 OS、SQLite、NATS 验证入口已经实际可用；避免为了语言统一另加未验证的 Node NATS 或数据库驱动。S 保持原 Session 及已有 loop，语言桥只传授权调用和原记录引用，不维护第二套模型/工具历史。两种语言的 IPC、打包和故障窗口是需正式用例验证的成本，不声称天然简单。

## 组件责任及交接方向

R 持有登记、权限、受理、输入/策略绑定、外部决定、运行/等待与交付责任。R 不声明 X 已停止，也不以续期令牌替代真实撤权；下层查证是继续依据。E 持有受控事件服务适配和固定输入文件视图，事件正文由 NATS 持有；持久提交关联复用 R。X 持有真实 Linux 环境/执行身份及原始结果；F 管理普通文件范围、版本和引用。S 持有原 Pi 局部 Session，其适配只补稳定绑定/持久确认/受控工具与 provider，R 仅引用它。调度器只能实施已接受外部决定，不根据工具成功或 done/fail 字符串自生策略。

引用至少明确 owner/kind、稳定身份/具体版本、授权范围；具体路径由当前环境解析，模型不能用任意宿主路径获得授权。跨组件交接不假设天然事务：提交前保留稳定完整绑定，已确认结果可查询；失回执按原身份查询，不能安全继续则显式保留未决和暂停。

## 正在细化的物理边界

任务容器不得拥有宿主权威目录的无限写入能力。X 与 F 联合论证有界私有工作副本、冻结/导出/实际停止后受控发布，分别限制数据、inode、日志、归档和元数据。恢复期间每个资源只有一个已验证写者，原代次变化拒绝发布。人工普通文件编辑进入同一协调；绕过协调的管理者改动使未确认输入失效，不假设不存在。

Harness/Session 工作进程不能因由管理员登记就获得宿主同 UID 的模型凭据或控制数据库读取权。固定源码和 Harness 代码在受限环境加载；其输入、工具、提交和 provider 通过按当前 invocation/资源/预算限权的桥交接。可信 provider 侧持钥，候选代码不接收真实 key 或可读路径。Surface 和模型输出只作为数据，不能被控制宿主 import/eval。

## 准备交付

每边界在 design/g3/<r|e|x|f|s|v>/ 保存职责合同、先行 case 表、真实依赖/替身范围、数值/故障域依据和准备判据。validation/components/<id>/ 是独立验证入口，只接受显式被测目标，缺失组件、缺失 case、错误证据和相关坏行为必须不通过。准备运行与未来组件正式运行分批，保留全部失败；准备阶段绝不以 fixtures 或 oracle 自测冒充组件实现通过。

根负责 R/E/V、总接口和覆盖；acceptance_evidence 负责 S；review_constraints 负责 X；long_task_drift 负责 F。先协调重大边界，再冻结其合同/用例并进行独立 D01—D05 审查。实现者不能自批自己的验收准备或正式能力。
