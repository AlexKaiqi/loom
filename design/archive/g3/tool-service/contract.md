## APIs and original facts

`ToolPlans(session_plans, snapshots)`; `prepare(binding, frame, original_session_snapshot_ref)` returns the complete original X schema1 request, original ordinary authority, original R resource/base/F view, deterministic import/materialize/install IDs and output paths, and original S owner/R parent association. It reuses SessionPlans.prepare for the original R/E/full-to-compact binding, then directly verifies SnapshotStore normal confirmation and original()/pending() over the stored Pi-format bytes. Binding and frame must exactly match the original pending; only `{target,script}` is delegated. Target runtime→R Surface/F surface/X runtime, workspace→R Workspace/F workspace/X task. Every input file remains present and checked; script bytes and cwd `.` are unchanged.

The existing shared X trusted configuration supplies tool-role limits. Ordinary authority is the original schema1 full caller/namespace/target/devino/revision/base/state_root/write responsibility/grants, plus the trusted slot tool grant; the Node allowed-entry list is not a Shell grant. `prepare` must not register an executable tool grant before a real matching R holder exists. A narrow internal grant step after R.acquire writes/registers the original immutable X grant; its full deterministic ref is already part of the R accepted payload. No peer-controlled profile/target/root/role is accepted.

`ToolService(control, files, execution, publication, plans, stopped_validator)` exposes:

- `execute(binding, frame, original_session_snapshot_ref)` → `{status,fresh,effect_id,result_ref,stdout_ref,publication_ref}` only on complete RECEIVED. UNKNOWN carries original IDs/evidence and is never a positive receipt. Invalid original scope fails before dispatch.
- `query(effect_id,binding)` is strictly read-only: original R request/receipt, X journal/blob and F/R historical facts. It does not call prepare, execute, publish, confirm or advance an unknown state.
- `reconcile(effect_id,binding)` may finish the same stopped execution's original import/install/confirm/release; it never calls X.execute, generates another execution identity or injects the result into orphan Pi pending. It returns fresh=false. If the current incomplete phase cannot be safely reconciled, return UNKNOWN and retain the original responsibility.
- `validate_publication(publication_ref,binding)` reads the original tool facility selected by `publication_ref.R_intent.execution_id`, verifies exact original binding and same full stored pub, original confirmed R installation/release, F original install/import provenance/rooted Git version and X original output refs. No side effects; later current directory changes do not invalidate earlier proven publication history.

Runtime invokes these methods with fixed host principal; the original parent source/principal stays in the R parent and accepted payload. Effect ID is the already checked Pi `s-tool-` digest of scope/operation/reserved result entry. R execution ID and X execution ID both use that exact effect ID. R execution payload retains `{parent_id,binding,frame,original_session_snapshot_ref,plan}` with complete original X request/ordinary authority, resource/base and deterministic publication IDs, not only digests. Changed same effect input conflicts.

## Ordered existing calls

Prepare original facts → R.accept(kind execution) → R.acquire same resource/base → register trusted matching tool grant → R.mark_dispatched → X.execute only if fresh → await_exit → original checkpoint s-tool-final → X.seal actual same object → actual original checkpoint bytes → F.import_archive into the original resource/version domain → F.materialize distinct staging → FilePublication.publish (actual R prepare_install/F install/query/R confirm/release) → X.release role after CID/volume removal → R.confirm_delivery positive. R holder remains until original stop+publication refs are established. X release only frees the role; retained original blobs remain charged by its actual retained_spool mechanism.

R positive receipt requires all actual X stopped, F publication+R holder release and X role release facts. Its facility_ref contains the unmodified original X responses/result ref/stdout ref and complete publication_ref; R wrapper carries its own full R digest/binding. No fields are added inside original X JSON. Error/timeout/partial output does not become COMPLETE or published; stop/cleanup preserves unconfirmed original bytes and responsibility. Query does not turn definite execution failure into business success.

Original receipt files are immutable serialized original responses, not a second result table. Their paths/IDs are deterministic from the original R request, and all associations resolve through R/X/F/S original stores. F checker wiring is a trusted owner callback which compares the original R tool plan/full context and actual X source/stop; no Peer.allow, arbitrary checker table or fixture index is used in product.
