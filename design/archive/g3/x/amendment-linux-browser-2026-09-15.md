# linux-browser 环境 profile：构建、登记与创建路径泛化（§5 流程修订）

状态：AMENDMENT_DRAFT_2026-09-15（契约级；无镜像构建、无登记、无用例运行）。依据：M06 契约（`design/g3/system/m06-browser-environment.md`，P1–P7）、`backend-seam.md` D-X-ENV-001 T0/T1、`amendment-environment-profile-2026-09-15.md`（registry schema 1 已落地）、`design/g2/adoption-assessment-2026-09-15.md` A1–A3（用户 2026-09-15 裁定并入本修订）。

## 1. 修订范围

1. **registry schema 2（增量式）**：`lore_execution/environment_profiles.json` 条目新增两个可选字段，缺省时行为与 schema 1 完全一致：
   - `seccomp_path`（字符串，相对 `lore_execution/` 的文件名；缺省 `"seccomp.json"`）——每个 profile 可绑定自己的 seccomp 文件；
   - `budget_maxima`（对象，键为既有 MAXIMA 键的子集；缺省空）——每个 profile 的预算上限覆盖，validate 时对该 profile 的请求生效 `{**MAXIMA, **entry.budget_maxima}`。
   `profile_sha256` 摘要覆盖全条目（含新字段），digest 语义不变。
2. **创建路径泛化**：`store.py` 容器创建从固定 `PROFILE["image"]` 改为按请求 `environment` 查 registry 条目取 `entry["image"]`；容器 seccomp 选项指向条目 `seccomp_path` 对应文件。
3. **引擎预检泛化**：`amendment-environment-profile-2026-09-15` 期间加入的"所有条目必须等于冻结 PROFILE"临时校验，替换为**逐条目身份校验**：每个条目 `image_id` 必须与本机镜像一致、`seccomp_path` 文件 digest 必须与条目 `seccomp_sha256` 一致、`engine_version` 必须等于宿主引擎版本。部署含义：**已登记 profile 的镜像与 seccomp 必须在本机存在**（登记即承诺）。
4. **linux-browser-v1 条目登记**：构建流程产出镜像 digest、依赖清单与 seccomp 适配文件后，以新条目登记（见 §3）。
5. **预登记组件用例 X031–X033**（cases.json 追加，UNVERIFIED）：profile 接受 + 预算上限生效 + 出网阻断留证。

## 2. 构建操作语义（采纳 adoption-assessment A1–A3）

- **A1-① 幂等**：构建输入只有 Dockerfile、固定基镜像 digest、钉定包版本；重复构建不依赖外部漂移状态。
- **A1-② 失败不替换**：构建失败或验证不通过时，registry 与活动 profile 不发生任何变化；登记只在构建+验证成功后一次性发生。
- **A1-③ 磁盘态**：镜像只承诺文件系统内容；进程、环境变量、内存缓存不属于 profile 资产，运行期进程归任务执行语义。
- **A1-④ digest 唯一身份**：层缓存只是性能手段；重建产物的 digest 若不同，则它是**另一个镜像**，必须走重新登记（保留旧值），不得原地覆盖 digest。

## 3. 构建与登记流程（§5-flow）

1. **构建资产**（预登记于本修订，随实现入库）：
   - `scripts/image-linux-browser/Dockerfile`：`FROM` 固定 v1 基镜像 digest（`python@sha256:78387bc3…`，沿用已冻结的 python 工具链）；Debian `chromium`（apt，构建时解析、版本记录进依赖清单）+ `playwright==1.62.0`（pip，精确钉定）+ 依赖清单生成步骤；容器内浏览器运行参数含 `--no-sandbox`（无用户命名空间的容器约束）。
   - `scripts/image-linux-browser/build.sh`：构建 → `docker image inspect` 取 `Id` → 输出依赖清单（包名+版本）→ 候选 seccomp 适配验证（`seccomp-browser.json` 从基线 `seccomp.json` 派生，按 chromium 实际所需 syscall 增补，验证方式：headless `--dump-dom` 冒烟在 seccomp+network=none 下通过）；任一步失败即整体失败（A1-②）。
2. **登记**：构建成功后一次性写入 `linux-browser-v1` 条目：`image`/`image_id`（构建产物 digest）、`seccomp_path`=`"seccomp-browser.json"` 及其 `seccomp_sha256`、`engine_version`（与 profile.json 一致）、`network`=`"none"`、`endpoints`=`[]`、`interpreter_argv` 同 v1 三形态、`budget_maxima` 初值 `{"memory_bytes":536870912,"pids":128,"cpu":2.0,"deadline_seconds":120}`（构建验证若证明可收紧则收紧后登记；登记后调整走修订保留旧值）。
3. **R 侧引用**：R 既有 `environment_ref` 字段解析到 registry 条目 id；本修订不新增 R 接口。

## 4. 网络裁定

`linux-browser-v1` 维持 `network=none`：M06 批量 A 的"容器内静态页面"经输入归档落盘、以 `file://` 打开（单页/表单/跳转均可离线完成）；N1（越权出网）的阻断事实即 `network=none` 的连接失败留证（脚本捕获并落产物，exit code 与产物共同留证）。P3 的 egress 允许表为**空集**的平凡情形；真实出网（受限出站端点+允许表）仍归 D-X-ENV-001 T1，不在本修订。

## 5. 预登记用例（X 组件级，UNVERIFIED）

- **X031** `linux-browser-v1` 接受路径：输入归档含静态页，python/playwright 读取标题写产物 → `completed` 且产物内容匹配。
- **X032** 预算上限泛化：同 profile 下 `memory_bytes` 超过 `budget_maxima` 上限 → `INVALID_REQUEST`（证明 per-profile maxima 生效而非全局 MAXIMA）。
- **X033** 出网阻断：脚本访问外部 URL → 连接失败事实落产物 → `completed` 且产物记录阻断（P3 证据）。
- 依赖：`real_docker`、`X_test_adapter`、`linux_browser_image`（镜像已在本地登记）。
- 用例机制约定：`profile_sha256` 使用占位符 `@profile_sha256:linux-browser-v1`，由 fixtures 在装载时从 registry 按条目 id 解析（与 X029/X030 的字面量不同，接受路径不能钉定尚不存在的 digest）；`request_overrides` 为浅合并，budgets 整键替换，因此 X031/X032 携带完整 budgets 对象；`browser_page_read`/`browser_egress_probe` 两个 fixture 脚本随实现入库（页面写 `/work/page.html`，经 playwright `executable_path=/usr/bin/chromium` 读取，结果写 `/work/result.json`，出网探测捕获异常后写 `{"egress":"blocked"}`）。

## 5a. 预登记调整记录（首次验证前，证据驱动）

- linux-browser-004/X031 证据：chromium 共享内存写 `/tmp` 失败（`No space left on device`，tmpfs 1MiB 为 v1 任务形状）→ `browser_page_read` 增加 `--disable-dev-shm-usage`；X031/X033 预算 `tmp_bytes`=64MiB、`shm_bytes`=16MiB；条目 `budget_maxima` 同步放宽 `tmp_bytes`/`shm_bytes`（摘要重算；登记调整发生在首次通过前）。
