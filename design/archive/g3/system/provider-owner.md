# ProviderOwner: R responsibility around the existing saved-wire bridge

Constructor: `ProviderOwner(control, root, endpoint, *, principal, budget=None, credential_provider=None, timeout=60, deadline_provider=None)`. `complete(scope, frame)` and `query(effect_id, scope)` retain the existing SessionService interface. `control_reference(ref, purpose, expected)` only verifies original provider receipt references. The same owner object is shared by Runtime and S. No model loop, no new effect ID, no second ledger, no real proxy in this preparation.

Trusted default budget is per complete `{namespace,surface_id,session_id,session_generation}`: 6 attempts, total 15360 input tokens, per-response 2048 output tokens, 300 seconds. `max_request_body_bytes` is an additional conservative preflight limit (default15360), not a replacement for actual reported input usage. There is no invented total-output limit. Constructor budget contains exactly max_requests/max_input_tokens/max_output_tokens_per_request/max_request_body_bytes/max_seconds. Independent scopes do not consume or block one another. A trusted optional deadline_provider(scope) supplies a shorter first deadline; otherwise the first R acceptance fixes monotonic now+max_seconds. The first scope R payload retains this original deadline/profile; later bound Bridge instances reuse it. Boot identity is retained so a new boot cannot extend an old monotonic interval. Query remains available after expiry.

Before any credential read, the existing Bridge validates full scope/frame/strict request. The accepted R invocation supplies namespace, original source-result and full Harness/capability association; input/session compact bindings are the already validated trusted S pending scope, never chosen from provider payload. R persists kind=provider_transport at the original effect_id with exact scope/frame/model_scope/fixed owner config/scope profile, then marks owner=provider dispatch before HTTP. Same ID different complete parameters conflicts. Confirmed and issued identities use only original Bridge.query. An old complete receipt is fresh=false and is never injected into orphan Pi pending.

Budget admission is serialized under the existing R lock but HTTP runs outside it. Original R provider intents count accepted/issued attempts; all existing Bridge prepared files of this root+scope must correspond to them. Completed original wire supplies actual usage; unknown/malformed usage blocks only new requests in that scope, not query. Count/input-byte preflight and scope deadline reject before accept/credential/HTTP. Current actual usage above the limit is retained and prevents continuation, never replaced by zero. Limits/endpoint/model come from trusted host config, not frame. No parallel per-instance counter can reset them.

R confirmed means a complete original transport receipt was verified, including its raw response, association and normalized/rejected conclusion. It does not mean valid model content or business success. Complete invalid wire may have a positive *transport receipt* while S remains paused; UNKNOWN does not confirm and no synthetic definite-negative/no-effect claim permits retry. The R wrapper holds full R20 association plus the original Bridge receipt reference and digest, not copied wire history. The reference callback reuses original R row under its lock and real Bridge readonly verification, with no nested transaction or writes.
