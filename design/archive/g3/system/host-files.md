# Trusted F source resolution for actual Runtime assembly

The Runtime calls existing FileStore capture/materialize/read_reference and original Git version validation. It does not copy validation Peer.allow, a mutable reference index or the fixture output catalog. Trusted startup configuration binds one namespace/principal, exact initial sources (resource/domain/absolute path/dev/ino/revision), and private host artifact/generated-input roots. These are configuration, not a ledger of task effects. The original R registration/installation and F rooted version/provenance remain the facts.

Initial capture is allowed only for a configured exact initial source or an actual currently authorized R root; host-created ordinary Harness/capability/generated inputs must remain below their fixed private roots. Historical reads retain original full F version and current logical-resource permission; they do not read a subsequently changed same-name file. F-view combines the original verified Git bundle with the exact current R registration inode only when the complete current tree matches that selected version. The full Harness descriptor and its actual retained code must validate; an arbitrary data file is not a Harness.

A Session locator is resolved only from an original S normal confirmation, matching scope. A continuation additionally names the original confirmed current R/S result and is validated by SessionDelivery before acceptance/application. No lookup-latest/repair/fallback. Source-result bytes come from resolve_original on the fixed previous normal S owner; no synthetic feedback result.
