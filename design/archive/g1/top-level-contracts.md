# G1 顶层抽象与契约草案

状态：G1-draft-3，等待独立反例审查与预注册模拟；不是生产API、产品选择或系统通过。前提：G0门槛见 ../reviews/g0-gate.json（244项原始要求）。本文的内部状态词用于论证，不新增模型可见业务协议。

## 1. 目的、边界与分层

Runtime负责使外部定义的推进在授权资源上发生，并保存已承担的运行责任。Harness负责投影、模型选择与交互、反馈解释和继续策略。最简串行Loop是一个外部策略实例，不能成为Runtime对所有事件或Shell结果的默认解释。

从上到下的依赖方向：

1. 外部任务与评测：准备输入、选择Harness、明确启动；业务产物由独立验收器检查。
2. Harness／orchestration：普通代码、模板和配置，通过公开底座契约表达投影与继续；不自带持久调度或环境管理真相。
3. Runtime契约及适配：事件交互、Surface接入、环境执行、解释外部定义及持久交接。决定实际权限、输入边界、已承担责任及恢复位置，不解释通用业务done/fail。
4. 既有能力：局部Session／执行器、持久事件/状态设施、普通文件与版本设施、Linux隔离执行后端。选哪个、是否多个职责由同一设施实现，在G2比较后决定。

向上交付的是获授权引用、结果与错误；下层不导入某份具体Harness策略。四项契约不是四个独立服务要求。一个复用组件可以承担多个契约；独立可验证不等于必须分别实现。

模型文本、Surface内容和事件正文均为数据。只有经过授权和完整性检查的调用才获得执行效力。Harness代码必须从其获准能力范围访问资源；是否能安全复用某Session的插件执行机制在G2验证，不能因代码由管理员登记就让模型生成代码获得Runtime管理身份。

## 2. 权威状态与引用

| 对象 | 唯一职责所有者 | 保留事实 | 其他层可持有的内容 |
| --- | --- | --- | --- |
| Surface | 普通目录及选定版本设施 | 模板、blocks、笔记、版本化材料引用 | Runtime保存登记身份/绑定与版本引用；Session可保留实际发送的模型输入 |
| Workspace | 普通任务目录及版本设施 | 仓库、数据、产物与相应版本 | Surface记录获授权的产物引用；不把Surface Git状态当任务代码状态 |
| 模型交互/局部工具反馈 | 选定Session／执行器 | 完整输入输出、调用身份、执行查询结果及其真实状态 | Runtime只记录推进关联和原记录引用，不复制成另一套竞争事实流 |
| 事件 | 选定事件权威设施及受控写入端 | 稳定身份、来源、持久受理与约定范围内顺序 | 输入目录仅是固定范围的只读视图；读文件不是消费确认 |
| 接入与运行责任 | Runtime及承载它的持久设施 | 对象登记/绑定/授权、输入与Step关联、环境引用、已受理下一步/等待责任 | Harness读取其范围内的输入和结果，不能改控制记录 |
| 外部副作用 | 实际目标系统 | 已发生效果、可查询身份与补偿结果 | Runtime/执行器引用其查询证据；文件回滚不改写外部已发生事实 |
| 开发验收 | 项目外部验证入口及证据包 | 契约/用例/实现版本、原始观测、失败和裁定 | Runtime只报告运行事实，不据模型最终回答裁定业务成功 |

必须保证的是每一事实有明确所有者与可验证引用，不是所有记录都在一个数据库。可接受受控导出/缓存，但需标明来源、版本及非权威性质。组件持久记录的原子范围、查询与引用生命周期均须G2实测；本文不假定跨设施天然存在事务。

## 3. 抽象身份、确认与输入契约

身份由调用设施生成和绑定，模型不发明请求ID。不同对象区分为提交、事件、登记、调用/Step、模型请求、执行操作、文件版本与策略版本；它们之间保留关联，不用一个时间戳冒充全部因果。

提交经历：检查来源与完整消息 → 在承诺持久范围内接受 → 实施请求（若适用）→ 完成事实。拒绝、接受和完成的回执不同；失回执为未知，先按同一身份查询/重试。相同身份相同内容可返回原受理关系；相同身份不同内容冲突。应用同名事件仍是应用声明，不能成为Runtime确认。登记完成不启动模型，初次调用由外部明确发起。

登记绑定对象真实身份、授权范围、Harness版本及可用执行资源。普通内容编辑不重新登记。目录移动/删除/身份替换或变更绑定必须显式处理；失效或歧义登记拒绝使用。已开始Step固定绑定版本，新绑定仅用于后续合法接入的Step，不静默改变进行中策略。

一次Step的输入定义为固定范围的事件/反馈、Surface版本/可读位置、可用目标、限制和局部记录引用。视图在完整可读后才交付，并告知真实位置；历史缺失、权限不足或失效引用是显式错误，不能伪装空输入。新事件在下一约定输入交付，不承诺运行中动态注入。

顺序最低要求是声明的事件读取范围内具有可复核位置和稳定身份，不假定跨来源全局因果总序。引用到历史内容需绑定实际版本和授权读取方式；仅有可变路径不足以证明恢复或跨Surface传递。保留范围不得删除仍被已受理责任依赖的记录；期限外恢复必须明确报告缺失，不能制造内容。

## 4. 运行责任与恢复交接

抽象的持久责任：一旦Runtime确认接受某次调用，须保持一份可恢复的未完成工作依据，直到该次调用按外部定义保存结果、明确暂停，或把后续责任可靠移交。它可以由既有队列、工作流记录或其他成熟持久设施承载；不要求新造任务状态机服务。

对于最简离散参考，逻辑阶段如下。阶段是可能由既有Session内部提供的可查询边界，并非要求外围重新实现其loop。

| 边界 | 必须能从持久记录判断的事实 | 中断后的合法动作 |
| --- | --- | --- |
| 调用受理 | 输入身份/范围、授权目标、策略版本、待执行责任 | 重建环境和查询阶段，不能依赖原worker内存 |
| 模型请求已交出、结果尚未确认 | 请求身份、已知发送事实或保守未知 | 查询原Session；无安全恢复能力则明确暂停，不把重新推理冒充恢复 |
| 完整模型结果已保存 | 原始结果的权威引用和相关版本 | 直接使用同一已保存结果解释；不能再次调用模型补写历史 |
| 执行请求已交出、结果尚未确认 | 稳定执行身份和可能已发生效果 | 查询既有执行器/目标端；确认未启动或具安全去重语义才允许重试，否则暂停 |
| 执行结果已保存、继续尚未登记 | 明确结果及仍未结清的策略决策责任 | 用保存的结果完成外部继续决定；不能因通知丢失变成永久孤儿 |
| 下一Step/等待已接受 | 已保存的后续安排、触发起点和所需引用 | 即使旧worker消失仍能发现并实施责任 |
| 本次回答/停止已保存 | 完整回答或具体停止原因，所用事实引用 | 结束这次调用；不封Surface永久终态，不等同于业务任务已验收成功 |

交接不变量：旧责任只有在新责任已持久接受，或本次调用按Harness定义可终结的完整回答/有依据停止结果已持久保存后才能结清。普通模型或工具结果保存只进入仍未结清的反馈解释/继续决策阶段，不能单凭其已保存关闭调用责任。在跨组件非原子窗口，可暂时同时存在可核对的责任与引用；重复交付须回到同一身份，不能成为重复实际副作用。只删除旧责任再发布新通知是反例。

外部决定也有明确接受边界：调用设施在首次相关交付前建立与输入/策略版本/阶段关联的稳定决定或请求身份；决定被接受后，其内容或权威引用必须保存，恢复复用同一已接受决定，不能再次运行不保证恒定的解释代码而静默换分支。相同身份不同决定内容按冲突处理，不能覆盖旧决定或发出新身份逃避核对。下一步或执行尚未启动不意味着决定尚未接受。

尚未接受的决定只有在能确认没有未核对的外部操作/提交、且重算不丢失任何已确认结果时才可从相同持久输入重新求值；如果是否已接受或是否产生效果不确定，先查询原身份或暂停。解释/继续代码自身的文件修改、模型调用与外部副作用同样经其获授权的受控边界记录和核对，不能以“只是回调”为由直接越过执行责任。此规则不要求整个Harness是纯函数，而是明确已接受决定与实际效果的保存责任。

任何已确认的模型结果、文件版本、输入和受理责任在承诺故障/保留范围内丢失均为失败。明确暂停只适用于预先声明的未知结果/不具安全继续依据的场景；不能用“无法确认”掩盖本应保存的状态丢失。

## 5. 等待和跨Surface推进

等待条件及信息传递由外部普通代码定义。持久安排至少需能重建：目标Surface/绑定、条件定义版本、事件匹配范围与起点、输入/产物版本引用、已经移交的交付关系。表示方式随既有设施选择，不为模型新增wait协议。

调用者定义条件起点时，应覆盖它希望消费的已发生事件。注册与扫描可以分开，但扫描历史/续读不能只依靠注册后实时通知；一次检查后订阅的间隙必须仍可重读。通知是唤起提示，不是唯一责任记录。重复通知/事件输入可出现，稳定身份使同一已处理输入不重做实际动作。

等待正式成立前保存必要状态、确认执行者实际停止/撤权并释放任务进程、连接和沙箱。共享Runtime/事件/存储可以常驻，不按等待任务保留一个阻塞worker或连接。活跃阶段允许保温。恢复后的公平调度在模型中以有限驱动轮次表示；真实延迟和容量由G3/G5预定负载验证，不能从有限状态模型外推。

多策略A/B及影子评测固定任务、初始文件、模型与预算，并使用不同可写资源和受控外部效果目标。比较器属于Runtime外部；若故障策略停止，其他策略不得因此得到写其资源的权限。两个Harness使用同样底座而非在Runtime中写两个分支。

## 6. 双域执行、写者交接与威胁边界

调用设施提交获授权目标、普通脚本和输入；Runtime在启动前解析对象真实身份并确定环境、cwd、用户/组、挂载、环境变量、端点/FD、网络及资源。一次调用固定一个环境；跨域通过第二次同入口执行及授权引用完成。cd、脚本文本、user字段、路径字符串前缀均不能取得权限。无权、歧义、未登记或失效目标拒绝，不回退宿主。

模型可见的Runtime Shell是受限工作身份，仅写自身获准Surface内容和临时区。任务Shell只写获准Workspace/输出/临时区，默认无控制端点和模型凭据。Model适配使用的凭据保留在受控调用一侧；文件不可见不等于开放FD或socket未泄漏。Harness执行方式也必须落实它实际需要的权限边界，不能通过插件上下文绕开任务隔离。

安全模型涵盖：不可信任务脚本/子进程、伪造调用文本、路径别名/链接、权限内误写、继承FD与端点、资源耗尽和网络越权。控制平面、内核及其管理员是信任基础；不声称防御被攻陷内核或恶意主机管理员。WSL只提供当前Linux验证环境，不是产品部署依赖。G2需以实际候选机制收紧或修正威胁实现，不得删上述任务代码边界来迁就产品。

写入协调以资源对象为单位，Surface和共享Workspace分别处理。候选首版串行策略：获取可写能力 → 在相同授权范围执行普通文件操作 → 请求停止/释放 → 由实际执行器或权限机制确认旧进程及派生写能力不再有效 → 授予新写者。控制租约失效或取消请求本身均不足以接管。旧状态不明时暂停该资源新写者，其他独立资源仍可推进。

人工编辑须作为可识别写入来源进入同一协调范围，普通编辑语义不变；不要求内容CRUD。主机管理员绕过协调的改动不能被假定不存在，应作为外部改变使相关未确认快照/引用失效并显式报告；不能对不受控制的并发写宣称一致渲染。如何冻结实际读范围、发现变化并阻止旧写能力，由G2/G3组件实验验证。

## 7. 文件版本、投影与可逆边界

Surface和Workspace单独选择必要版本，但恢复以明确组合列出：内容版本、策略/模板版本、输入起点、Session/执行引用、环境/依赖版本、未结责任及外部效果引用。选择回退一域不能伪装另一域或外部世界已回退。回退自身是新的可追溯事实。

快照必须覆盖承诺恢复所实际依赖的内容，包括未跟踪文件；只捕获Git HEAD不是完整判据。接受的输入/快照必须在承诺的写入协调边界内一致；若只能获得混合或已失效版本则拒绝确认，不能用事后文件存在证明先前模型看到了相同内容。

Harness投影选模板、blocks、事件/反馈和正确执行路径。裁剪仅改变可见视图：标记被裁剪、提供获授权完整原始来源、保留未知执行的核对责任。模型完整输出才按所选交互约定解析；截断、格式错误或未完成请求不得成为普通最终回答，普通代码块不自动成为执行请求。

## 8. G1论证范围与G2证据债务

G1需检查的是以上抽象是否自洽、关键失交接/越权/混淆状态的反例能否被拒绝，以及独立组件边界是否足以安排研究。模拟之前单独冻结 cases-durability 与 cases-boundaries 的输入、预期及错误对照；版本在提交后记录。允许从模拟反例修订本草案并保留旧版本。

有限模型只假设并检查：受确认持久记录在故障中保留；已有身份能关联查询；授权/撤权机制按其结果生效；选定范围快照可一致读取。它不能证明磁盘fsync、消息服务配置、真实进程树停止、链接竞态抵御、Linux限额、Session恢复或真实模型兼容。上述能力在G2相关框架实验中直接查证；任何缺口回到此契约，不以模型通过取代。

未知项Q01—Q08/Q15的语义由本草案和独立模拟处理，真实能力仍OPEN。Q09模型代理、Q10具体Linux设施、Q11负载阈值、Q12策略比较协议、Q13/Q14项目研究范围按原到期门槛执行。G1结束只冻结足以研究的边界，不提前承诺未经运行验证的组件或性能。
