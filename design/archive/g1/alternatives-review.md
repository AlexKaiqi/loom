**AR-01，OPEN：外部解释/继续决定的接受与重算边界。** 草案 L56/L58 允许从已保存结果继续运行解释/决定代码，L62 要求重复交付回到同一身份，但尚未明确外部决定本身何时被接受、已接受的决定如何锁定身份/内容，以及未接受决定可以重算的前提。V:58/106/116 不要求含模型/普通代码的推进成为恒定纯函数。反例：解释代码依据可变输入或随机性产生决定甲，甲已被下游接受而旧责任尚未结清；恢复重交付后重新运行得出决定乙，以新身份再提交，造成分支替换或第二次效果。若解释代码本身有副作用，简单重跑也可能重复它。

应在契约明确：已接受决定/执行意图绑定稳定身份、原输入和策略版本，恢复复用其已确认内容，不能重新解释覆盖；未接受决定仅在没有未确认副作用或已完成安全核对时重算；解释阶段的实际副作用也受既有通用执行、记录和结果查询边界约束。此要求不把全部 Harness 冻结为纯函数，也不新增模型可见决策协议。对应模型需保留“决定未接受/已接受但交接未结清”的差别；G2 核对 Session/适配能否持久查询决定或等价受理事实、重复身份是否拒绝不同内容。

其余真实能力仍按 H01—H10 作为 G2 证据债务，当前未发现另一处需要提前冻结产品/语言或扩大目标才能解决的路线冲突。

## 1. 比较准则

必须同时保留：外部策略表达、底座的持久运行责任、真实权限与写入协调、约定已确认状态及历史、普通代码/文件语义（V:9–28、60–74、105–116）。符合这些性质的不同实现可以竞争；仅因某条路线更易画成状态图，不构成采用理由。

候选路线只有在实际前提成立时才能支持其结论。G1 应显式保留“请求已发出但未确认”“效果可能已发生”“旧执行者可能仍可写”“快照尚不完整”等中间状态，不能把困难藏进一个总会成功的抽象调用。结构论证及有限模型结果不证明这些真实调用具备相应语义。

## 2. 外部策略与局部 Session 的交接

关联：Q01、Q08、Q12；V:60、105–116、200–226。

| 路线 | 必要性、收益与限制 | 当前裁定 |
| --- | --- | --- |
| 普通外部策略，经已有 Session 的配置、回调或阶段接口定义投影/模型/反馈/继续；Runtime 保存自己受理的交接责任 | 复用局部模型—工具循环和权威历史，避免另一套局部真相。前提是 Session 真正允许必要策略外置，提供可定位结果、继续点与实际执行衔接；并非任何可启动的 Agent 都符合。 | 保留为主要待验证路线；调用粒度不预先冻结。 |
| 同一外部契约下采用更细阶段适配，补足已有 Session 缺失的结果关联或交接 | 可定位具体能力缺口，仍保留局部事实归属。新增适配必须有缺口证据；不能借适配名义完整重做同一个局部循环或持久底座。 | 合法备选，适配量与必要性由 G2 决定。 |
| Runtime 写死“每次工具成功就调用模型、某事件即继续、固定投影/终态”等统一 loop | 单样例可能简洁，但更换策略需要修改底座，无法表达不同继续规则。Runtime 的通用分派、记录和恢复机制本身并非被禁止的策略 loop；问题是把业务选择写死。 | 不满足目标，作为反例。 |
| Runtime 仅启动拥有全部等待、调度和恢复的黑盒 Agent | 缺少可恢复交接与结果查询时，外层无法区分已完成、待继续和未知效果。进程存活承担责任，退出后只能重跑。 | 不满足目标；不能用“插件化”或包装脚本自证。 |

不透明的内部实现不是自动否决理由：若现有 Session 对外提供足够且可实测的控制、记录与恢复契约，其内部仍可实现自己的局部 loop。反之，接口名字叫 resume、session 或 callback 不构成能力证据。

应保留的反例：

- **A-R1**：相同输入和 Shell 明确结果，外部策略甲继续、乙停止；实际行为却都继续。由此拒绝底座硬编码策略，即使两者初始任务都能完成。
- **A-R2**：模型结果已被局部执行器保存，但 Runtime 尚未登记继续责任就崩溃；恢复只认“本地进程退出”，从头重新调用模型。应暴露交接/查询缺口，而非将重推理算作结果恢复。
- **A-R3**：推进已接受策略版本甲，文件切换到乙后恢复悄悄采用乙；或仅存一份可变 Session 路径导致历史结果变动。模型须关联已接受版本及稳定记录身份。

G2 支持证据：固定候选版本后，从局部原始记录及外部调用观测核对两份策略差异；终止旧进程/缓存后按原身份查询已存模型/工具结果及继续点。找不到结果或必须依赖旧进程，即推翻该候选的相应假设；不能以重跑产生近似产物替代。是否需要更细适配必须由具体缺口回答。

## 3. 持久待处理责任与环境重建

关联：Q02、Q03、Q07、Q11；V:20–22、89–99、123–155、202–226。

| 路线 | 必要性、收益与限制 | 当前裁定 |
| --- | --- | --- |
| 在同一受验证持久提交边界内保存可关联的结果/输入和下一步责任，再由共享执行机制领取 | 减少跨记录交接间隙；依赖相关权威对象确实能处于同一保证范围。不能假设进程、文件、远端效果、事件服务天然共享事务。 | 可建模比较，不预设具体存储或全局事务。 |
| 保存各自权威结果与可查询交接身份；接管/重启时从持久事实核对未完成交接，再恢复交付 | 允许复用多个既有组件，不复制另一份局部真相。代价是必须定义每个未确认状态、重复处理及补齐规则，通知仅用于加速发现，不能是唯一责任载体。 | 可建模比较；需要证明不存在“双方都以为对方负责”的空隙。 |
| 每个任务保持阻塞进程、长连接或不可重建协程状态等待 | 容易保留栈与局部变量，但任务生命依赖专属活资源；把这些进程放入共享 Runtime 目录或进程管理器不会改变归属。 | 不能兑现等待资源归零与重启接续。 |
| 仅保存文件快照，继续依赖一次通知或内存队列 | 文件内容可能完好，已受理的继续责任仍可能永久丢失。 | 不足；内容恢复与交付恢复需要分别成立。 |

共享 Runtime、消费者与调度设施可以常驻；持久任务记录和共享索引可以存在。不能把“每任务一个逻辑记录”与“每任务必须存活的执行过程”混同。活跃执行允许保温，进入等待/非执行期才检验任务专属进程、连接与沙箱归零；具体资源归属和进入边界必须明确。

应保留的反例：

- **W-R1**：先查询未见目标事件，事件随后发生，最后才登记等待；若仅订阅新消息，责任永久挂起。须用明确输入起点与可恢复历史处理间隙。
- **W-R2**：输入已被认为消费，结果尚未保存时崩溃；或结果已保存，继续安排尚未保存时崩溃；或继续安排已保存，但通知丢失。每种状态都须仍能查询原身份并恢复责任或明确未知，不能全部抽象为一个原子“完成”。
- **W-R3**：沙箱已销毁，每个等待任务仍有 Agent/长连接；或共享消费者重启后丢掉仅在内存中的任务继续点。仅检查沙箱数量会错误通过。
- **W-R4**：依赖不可用或永远不被调度，却在有限模拟末尾把 pending 清空或声称最终一定推进。安全性与活性要分开：不丢已受理责任可无条件检查；最终推进还依赖服务恢复、保留期和公平调度等已声明前提。

G2 支持证据：在实际组件中核对保存确认、请求身份、重复查询、消费起点与保留规则；在上述交接间隙杀进程/断通知，清除任务内存与沙箱后查询持久责任。从 OS/执行器/连接侧计量等待资源。确认早于持久保存、无法查回未决身份、事件保留无法覆盖承诺，均应推翻相应方案，而非修改“已受理”的口径避开失败。

## 4. 真实授权与写能力撤销

关联：Q04、Q05、Q10；V:70–88、181–196。

| 路线 | 必要性、收益与限制 | 当前裁定 |
| --- | --- | --- |
| Runtime 在启动前解析获授权目标并落实身份、对象、挂载/端点、网络与资源边界；普通代码在真实受限环境执行 | 权限不依赖模型守规矩。路由与授权分开：位置可帮助选择环境，但不产生权限。一次执行一个确定环境。 | 必须满足的语义；实际隔离技术待 G2。 |
| 接管前停止旧执行者及相关写入后代，确认实际停止后才让新执行者写同一权威资源 | 容易陈述安全先后关系，但停止请求可能延迟或失回执；不能把发出取消等同于停止。远端或脱离的写入者也要在所承诺边界内处理。 | 可验证路线；停止确认失败时不应双写。 |
| 在执行/存储实际强制点撤销旧代对权威对象的写能力，并核对旧代已不能产生有效修改，再交接 | 可以不依赖旧执行者主动退出，但撤销必须真正作用于已有句柄、后代及允许的写通道。隔离旧私有副本只有在其确实不能再修改当前权威对象时才成立。 | 合法备选假设；“令牌已过期”或更换目录名不足以证实。 |
| 根据路径字符串前缀或脚本 cd 选择高权限宿主执行 | 路径别名、链接、替换竞态、同一路径的多环境含义都可越过字符串判断。 | 不满足真实授权契约。 |
| 仅改 lease/owner/epoch 字段，旧进程仍持有可写 FD 或控制通道 | 逻辑记录看似只有新 owner，实际仍能覆盖 Surface/Workspace；普通 Shell 写入不会自动重新检查控制记录。 | 不满足真实写能力撤销，作为必须能检出的反例。 |

应保留的反例：

- **P-R1**：授权检查之后、实际打开之前目录绑定或链接变化；或者目标相近前缀导致误授权。模型不能预设“路径解析已正确”而将所有相关拒绝检验省掉。
- **P-R2**：旧执行者预先打开可写文件，接管后执行延迟写；再加入子进程、继承端点及允许的远端写入口。控制记录唯一不等于写结果唯一。
- **P-R3**：Runtime Shell 可编辑自己的 Surface，但通过继承的管理 FD 改写权威事件或另一个 Surface；目录不可见不能证明控制端点未泄漏。
- **P-R4**：取消请求已保存，旧进程仍在写；系统把它标为“等待且资源归零”，并启动新写者。撤销尚未确认应保持可辨识的中间状态，不同时宣称交接完成、实际停止和资源释放。

G2 支持证据：从实际 Linux 身份、对象侧结果、进程树和开放端点进行独立观测；用延迟写/已有 FD/子进程验证“撤销后不得改当前权威对象”，用授权成功与代表性越权失败验证双域执行。无法影响旧句柄的机制不能仅凭其 API 名称作为撤销方案。WSL 证据注明环境；生产内核与后端相关承诺仍需目标 Linux 条件验证。

## 5. 版本范围恢复与动作重放

关联：Q02、Q06、Q07、Q08；V:72–82、149–163、175、194–196、332–336。

| 路线 | 必要性、收益与限制 | 当前裁定 |
| --- | --- | --- |
| 对约定受管理状态形成可重建版本集合，分别记录 Surface/Workspace 并关联 Session、输入、Harness 版本及必要环境依据；恢复时显式选择有效组合 | 直接满足状态可追溯与继续依据，允许分别回退两域。需要定义恢复集合闭合和组合有效性，不能只记录会变化的路径或某个版本号。 | 需要进入顶层契约；具体格式与版本产品未定。 |
| 在已确认停止/协调写入的边界捕获版本 | 易于获得一致恢复集合；代价是边界与写入协调。不能宣称多文件天然原子。 | 可建模路线，不要求每次编辑都提交。 |
| 使用具备一致读视图/版本关联能力的在线捕获机制 | 可减少停写，但依赖实际机制对跨文件、引用、未跟踪内容和外部记录的承诺；几个独立快照不自动构成一致组合。 | 合法备选，G2 能力证据是前提。 |
| 回放既有事实以恢复索引和待核对责任；实际动作另行按原身份查询、判定与执行 | 复用事实记录；避免把历史事件中的文字直接当成新的命令。待处理责任恢复可触发合法调度，但必须与已完成效果重复执行区分。 | 合法恢复步骤，不能独自证明文件或远端效果已回退。 |
| 重放历史命令或重新调用模型，以重新生成近似最终文件 | 非确定输出和不可逆副作用可能重复；即使报告相同也未恢复原模型结果或原确认事实。 | 不可作为已确认状态无损接续的替代证据。 |

应保留的反例：

- **V-R1**：Surface 指向报告路径，路径随后被改写；仅保存 Surface 版本或文件系统目录名，恢复读取到新报告。需定位引用所指版本及其实际可访问内容。
- **V-R2**：快照只包含已跟踪文件，恢复依赖的未跟踪数据/环境依据缺失；或跨文件保存中断，组合不存在任何承诺的一致边界。不能用单一 HEAD 或摘要证明集合完整。
- **V-R3**：远端效果已经发生但回执丢失；文件回退后再次执行同一动作造成重复效果，或者删除历史记录假装动作从未发生。应保留身份、查询结果或安全暂停，不虚构通用外部回滚。
- **V-R4**：事件历史回放时重新触发已完成动作；或恢复程序重新调用模型后把新答案当成旧答案。需区分事实重建、未决责任查询和实际执行。

G2 支持证据：以可独立识别的两域版本、未跟踪但在范围内的文件、变化引用及目标端效果计数为对照；在捕获、确认和回执边界中断，删除旧环境/缓存后恢复。核对原模型结果身份与内容，已完成效果不被再执行，回退本身和历史仍保留。外部系统不具备查询/幂等/补偿时，只能支持已明确的暂停或受限恢复结论，不能临时扩大自动恢复承诺。

## 6. 模型必须外显的真实能力假设

以下 H 标签用于防止把基础能力直接假设为“已经验证”。每项均仍 UNVERIFIED；模型中的假设成立最多支持条件性逻辑结论。

| 假设 | 模型不得隐藏的条件 | G2 如何支持或推翻 |
| --- | --- | --- |
| H01 确认后的持久性 | 何时算已确认、哪些故障后仍可读、保留/删除边界。未确认与确认状态必须分开。 | 保存确认附近中断并重启，从权威记录查回身份/内容；确认后丢失即反例。 |
| H02 可关联查询与结果恢复 | 局部 Session/执行器的身份稳定、结果可查询、必要继续位置可重建；结果未知不被强行二分成功/失败。 | 关闭旧进程/连接后按原身份查询结果及继续点；只能重跑或依赖缓存则能力不足。 |
| H03 交接可补齐 | 同一提交边界或跨组件核对协议覆盖每个中断点，通知不是唯一责任。没有默认全局事务。 | 分别中断保存结果、保存继续安排、发送通知，核对责任不出现空隙或无依据重复执行。 |
| H04 授权在真实强制点生效 | 请求获准不等于执行环境已受限；真实身份、对象、继承句柄/端点及限制都在承诺范围内。 | 授权正例和路径/身份/FD/资源负例，从 OS 与目标对象侧观测，而非读调用参数。 |
| H05 撤销真正阻止旧写者 | 已发取消、已修改 owner 与停止/失写能力是不同状态；已有句柄和后代不被假设消失。 | 接管后旧 FD 与后代延迟写当前权威对象，任何成功都推翻相应撤销完成判断。 |
| H06 版本集合完整且组合有效 | 包含承诺的实际依赖与版本引用，协调/一致视图的保证明确；不默认多文件原子。 | 在捕获中间修改文件、引用与未跟踪依赖，再无缓存恢复，比较实际组合与独立预期。 |
| H07 外部效果可核对或明确暂停 | 不假设所有远端操作支持幂等、查询或补偿，也不把文件回退视为效果撤销。 | 效果发生后丢回执，核对真实效果与查询能力；不支持时必须保持未知/暂停及未达承诺范围。 |
| H08 重建不依赖旧环境 | 环境/依赖/输入版本可取得，持久状态不藏于临时沙箱；模型密钥不默认下发任务。 | 删除原沙箱及缓存后重新构建并查询状态，验证条件与所需引用真正可用。 |
| H09 最终推进的活性前提 | 服务最终恢复、必要历史未过期、调度公平或具有明确进展条件；不将无界故障假定为即时恢复。 | 在定义范围内恢复服务、丢通知并持续观测待处理责任；超时结果按预定判据记录，不用有限次数成功证明无限可用。 |
| H10 策略扩展与事实归属 | 所选 Session 的扩展点足以外置必要策略，且权威结果能够被 Runtime 引用而不是复制竞争记录。 | 保持底座不变运行不同外部继续规则，直接核对局部结果、实际调用和接续接口；无扩展能力则淘汰候选或记录必要适配。 |

Q15 的开发验收设施与上述 Runtime 事实责任分开。独立检查应直接观察产物和拒绝反例，不把模型中某变量设为 verified、另一个 Agent 同意或状态名叫 accepted 当作现实证据。共享同一可写用户目录仍不提供防篡改隔离。

## 7. 给顶层契约与预注册模拟的审查要求

1. 四组路线分别声明受保护性质、可行备选、选取当前建模路线的理由与实际能力假设；不把本轮选取的有限模型当作唯一产品架构。
2. A-R1—A-R3、W-R1—W-R4、P-R1—P-R4、V-R1—V-R4 是待预注册覆盖的反例方向，不是已经执行的用例。相同机制的检查可合并，但不得因此删除关键中间状态。
3. 输入身份、保存模型结果、继续责任、写能力、版本集合和外部效果必须能够分别观察；不能用同一布尔 success 同时证明它们全部成立。
4. G1 模型若直接假设 H01—H10，应同时给出其反面时哪项性质不再成立以及 G2 的验证责任。模型中通过不关闭 Q01—Q10 的运行能力未知项。
5. G2 不支持某个候选能力时，先拒绝该候选或论证必要适配；若发现顶层假设本身矛盾，返回 G1 修订受影响模型和契约。不得为保留候选而缩小原始必须项，也不在尚未证实的抽象上继续生产实现。

本文件只完成 G1 独立审查的路线/假设部分。尚待根 Agent 的顶层契约、预注册用例及模拟结果形成后，按同一原始目标进行后半段一致性与反例覆盖审查。
