# X 普通工具目录容量：既定 S027 接线缺口

状态：先行变更论证，未修改产品；等待独立核对。来源：S 原合同 S027 要求实际普通工具遍历 64 目录 × 8 文件及长 diff；X 原 requests.py 的普通工具私有卷上限为128 inode，因此包含所有原工作空间的合法输入无法装入。Node XN12只验证 Session 只读读取该目录，不能替代普通工具执行。

最小变更只将普通工具可请求的私有卷 inode 上限从128增至1024，沿用现有字段、tmpfs配额、真实grant与slot计费。常规工具仍请求原128；S027请求1024，不删除/只挑选工作空间内容，不给工具额外宿主挂载或控制权限。原6MiB字节、128MiB内存、.25CPU共享角色与3对象、整个slot128MiB/8192inode不变。S512+tmp2048+shm64，tool1024+tmp64+shm64，helper128，加三个控制预留384及少量原目录，仍低于8192；实际保留spool另由现有slot admission计算，不以静态加总豁免。

实现前用例：复用已接受F-large实际578成员/513文件原输入与原 X schema1 driver 请求构造；普通脚本在真实工具环境逐字节hash全部普通文件及遍历成员，输出独立从源字节得到的完整集合摘要。保持原128请求时相同输入不得成功导入；明确1024的新合法请求须完成且与原F源一致。另实际写满1024 inode得到ENOSPC，deleted-open原债务不得消失，清理后原namespace/CID/卷不存在。1025预算无实际对象创建即拒绝。旧原128 inode配额边界与共享slot计费回归复用原 X023/XN11机制并直接检查。

判据与原件在修改 requests.MAXIMA 前固定；只运行受影响的普通工具容量用例，不重复不受影响的Pi/Node权限/通道整组。原128的过去容量范围仍如实保留；新增容量须有独立实测通过后才能进入S027。该纠错不改变原S27/150或系统规模指标，也不新增模型工具、协议或状态表。
