# Trusted original Session reference resolution

`SessionSources(control, snapshots, delivery, initial_session_ref).resolve(ref, purpose, expected)` is a readonly adapter over original R rows, `SessionDelivery._verify` / its injected actual `SessionFacts.read`, normal SnapshotStore ownership and `resolve_original`. No ledger, replay, Engine call or model call is added by this adapter. Actual SessionFacts may independently inspect original Engine identity when wired in the Runtime; the finite host probe uses explicitly labelled Facts fixtures and does not claim physical verification.

The fixed initial ref is exactly `{owner: S, namespace, surface_id, session_id, session_generation, confirmation_request_id: null}`. `expected.invocation` must match the immutable accepted R invocation under the delivery principal's actual R authority; caller-supplied expected cannot replace the R row. Initial `session` requires that exact ref, explicit null `source_result_ref` and null `input_binding.previous_session_ref`; no SnapshotStore mutation is performed.

For continuation, the current original invocation selects `source_result_ref.operation_id` and an exact `{owner:S, kind:confirmation, confirmation_request_id, session_scope}` locator in both `session_ref` and `input_binding.previous_session_ref`. Resolve the original fixed drive execution ID for that preceding operation; its R row must be confirmed and its exact original receipt must pass `delivery._verify`. The preceding/current namespaces, Surface, full Harness and capability refs agree; the source locator equals the actual saved frame result. The actual normal owner scope and complete original Node compact binding agree. Missing/issued/invalid receipts, swapped owner/Session/generation/result/compact refs and quarantine never become healthy sources.

`session-source` accepts only the exact original `expected.facility` R row and its saved receipt for the expected current parent/action (accept or drive), verifies those original facts, and returns `{facility_id, confirmation_request_id}`. `session` returns `{scope, confirmation_request_id}`.

`source-result` requires the original current payload source and the same continuation checks. First call the existing `resolve_original` with its original binding and normal confirmation. Then read that validated archive again with exact hash and extract the actual `pi.result` value token through existing `rows`; its SHA must equal `result_sha256`. Return those bytes, without Python JSON transcription. It is original Pi result bytes, not a new prose summary or reconstructed tool history.
