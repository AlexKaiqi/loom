# Ordinary Runtime Shell application emit

Source: v5 5.1 lines141–151 (authorized request/receipt, local bytes are not acceptance, fixed next-Step input), 5.3 (Runtime/task separation), 6.1 and original M01 one authorized notification. No new X channel, permission profile, F projection, event ledger or model loop.

## Transport and truth

schema1 X has ordinary finite/duplex stdin/stdout but no extra endpoint/RO-mount field; endpoints=[] remains. Node schema2 mounts do not grant ordinary Shell access. Stdout/stderr stay ordinary output. A fixed ordinary helper appends application data to `/work/.lore/emit-requests.jsonl`; the whole file remains in the original checkpoint and full F published version. It is an application request file, not accepted-event history: R/E/NATS alone decide admission/delivery. Existing user bytes are never hidden, removed or rewritten by Runtime.

The helper is ordinary standalone Python code, explicitly supplied as a fixed code document for `python3 -c <that exact code> NAME JSON_PAYLOAD`. No fictional PATH `emit`, injected mutable parent files, key/SDK/socket or control handle. `emit_local(root,name,payload)` is its local filesystem function; physical Runtime call root is `/work`. NoEngine tests supply a real private directory. The CLI returns `{status:"LOCAL_STAGED",id:<local ordinal>}`, not accepted/saved-by-E. Actual X integration later verifies the exact helper source/script and ordinary private path.

## Fixed finite M profile

Only `.lore/emit-requests.jsonl`; `.lore` must be an ordinary directory if present, file must be an ordinary independent regular file, no symlink/hardlink. Every line is complete strict UTF-8 finite JSON plus LF, exactly `{id,name,payload}`; id is a 1-based absolute ordinal generated by the local helper and independently checked by host. Local ordinals grant no global identity. Name is nonempty text; payload has the existing E data semantics (top-level origin/principal/system prohibited). Runtime cannot infer policy from names, including done/fail/surface.registered; E.submit always application origin.

M limits fixed before runs: total outbox bytes<=65536, total records<=64, encoded line<=8192, new records per original tool<=8. These are finite current helper limits, not new system throughput claims. Concurrent local helper races may fail validation; no local lock/receipt/progress database is created. Partial append, rewriting/removing an old prefix, wrong ordinal or excess is explicitly rejected, not silently truncated. A new file starts from empty; unchanged file yields zero events.

## Minimal trusted interface

`EmitService(events,resolve_tool_source).publish(effect_id,binding,publication_ref)` is async and a write operation. Resolver is supplied by ToolService and rechecks its actual R execution, original X source and real F/R publication, never a caller-provided authority tag or new catalogue. It returns `{principal,namespace,domain,emit_allowed,execution_id,effect_id,binding,frame,base_archive_ref,output_archive_ref,publication_ref}`. Base is a complete original F archive file ref `{path,bytes,sha256}`. Output is original X full checkpoint `{path,size,sha256,owner,execution_id,source_binding,...}`. Frame is the original S pending tool frame. Caller inputs must equal these original records. Permission must be runtime domain + explicit emit_allowed and original namespace/principal; task domain has no submission grant.

The adapter rechecks full binding/effect formula, domain/source, actual archive bytes, publication's same execution/resource/base hash/output hash and confirmed release, then uses the existing F ordinary archive codec to inspect the full base/output. Only a complete appended suffix is submitted, after all rows/limits validate. It does not mutate source archives or publish files. F publication and R tool-plan authority have already been established by the trusted resolver; archive fixtures alone cannot prove those facilities.

Actual event ID=`emit-`+SHA256(canonical([namespace,binding.operation_id,effect_id,absolute_record_ordinal])). It excludes content, so changed same-ID content conflicts rather than evading the old ID. Host sets E context=trusted principal, namespace from original scope, and uses `E.submit(context,id,namespace,name,payload)` only. Every retry keeps this ID and content. Existing E.accept/mark_dispatched decides a fresh permit: accepted-but-not-dispatched may advance once; issued UNKNOWN only queries original E/NATS and never issues another PUB. Adapter has no private retry loop or low-level NATS call.

Return a list of original E responses. Stop after UNKNOWN/ACCEPTED; retain the original R tool responsibility and checkpoint for explicit reconciliation. Definite REJECTED remains negative. These responses are separate from original X result_ref/stdout_ref and publication_ref. ToolService query never calls publish; execute/reconcile can use this write port. Since S tools are synchronous and E is async, Runtime must bridge to its existing owning event loop, not asyncio.run the same NATS client in a new loop.
