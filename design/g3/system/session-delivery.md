# Original R responsibility to Session delivery

This refines the accepted Runtime/S integration map, without changing R/X/Pi schemas or creating a Session ledger.

- Original parent is the accepted R invocation. For accept/drive, the trusted host assigns `execution_id = "s-exec-" + sha(canonical([parent_id, action]))`; the original R facility request uses the same ID, parent namespace, kind=execution and the fixed host runtime principal. Its exact payload is `{parent_id, action, execution_id, node_request}`. The complete Node request is retained, not just its hash. R marks fresh dispatch before S/X; issued identities only query original X/owner evidence, never replay an older accepted Session or generate a new effect ID.
- Each SessionService invocation has one fixed terminal checkpoint ID `s-service-final`; its normal confirmation request ID is the already defined `"s-" + sha(canonical([execution_id,"s-service-final"]))`. Intermediate pending checkpoint IDs remain distinct. A preallocated `{owner:S,kind:confirmation,confirmation_request_id,session_scope:{namespace,surface_id,session_id,session_generation}}` is only a locator, not admission/ownership evidence. Only a real normal SnapshotStore.query and exact original execution/binding/source validate it. Quarantine never supplies this source.
- accept starts from parent.payload.session_ref (previous explicit Step or true initial). drive starts only from this parent's confirmed accept facility and that exact normal S confirmation. query/export_read choose a confirmed drive original when available; an issued/unknown drive must not fall back to an older accepted original. Node compact input/harness/capability/source binding is stable within one parent invocation; input identity cannot depend on the per-action X execution ID. A new explicit invocation chooses the new fixed input.
- A Runtime wrapper of actual facility output is retained by R.confirm_delivery. It has complete original R20 expected request_id/namespace/source/delivery_owner/request_digest, definite/outcome and digest, and a facility_ref with owner=X, kind=session_execution, execution_id, confirmation_request_id, complete node_request_digest, actual unmodified original_execution_response and actual normal session_confirmation (or explicitly unadmitted quarantine). It is a host projection of original X/S evidence, not a claim the extra fields were emitted by X. The checker must query original X identity/record and S original owner; same physical completion does not mean Session admitted or business success.
- A trusted session-source resolver returns only facility_id and confirmation_request_id. SessionPlans independently reads the real R row/phase/full payload and registered receipt validation, then reads S confirmation and the complete original binding. Caller-provided old or invented owner/envelope cannot select the source.
- External Harness may propose a next Session via the preallocated terminal locator, but submission and application must validate that it now resolves to the actual retained current result. R's generic selector validation alone does not perform that check. Runtime validates then submits exactly the original external body, without adding stop/successor policy.

The readonly runtime_context.execution_id is the stable parent drive execution ID for accept/query/drive configs alike, so its locator is exactly derived from that ID. The actual X request.execution_id remains the real per-action execution. This context is policy input, not an extra authority or execution ledger.
