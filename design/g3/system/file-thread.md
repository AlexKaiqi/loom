# Existing F signal-window calls on the Runtime main thread

This narrow amendment answers the actual fixed-author-001 failure: RuntimeFlow executes Session in a worker, but F StableWindow requires Python's signal-owning main thread. Original FileStore/window/installer semantics and gates remain unchanged.

Source audit: `FileStore.capture` and `Installer.install` enter StableWindow; `Installer.query` also enters it while validating not-installed/installed layouts. `import_archive`, materialize and historical reads do not enter this window and remain inherited original methods. query_install is a read of the original installation, has no authority/checkpoint/R callback, and must still inspect actual roots/bytes.

`RuntimeFiles(...original FileStore arguments..., control=<actual ControlStore>, delegate_timeout=30)` and `bind_loop(loop)` form the complete added API. Binding occurs only on the main thread to its running loop, once (same-loop repeat allowed). Main-thread calls use the original methods directly, including startup before Runtime.open. A worker delegates only capture/install/query_install to that loop using call_soon_threadsafe and a concurrent Future. Inputs are detached before queueing. No new process, file registry, receipt, or replay queue.

A worker owning the original R._lock must not delegate capture/install: their authority callbacks can read R and deadlock. These calls reject UNSUPPORTED before enqueue. query_install is the audited exception because it invokes no R callbacks; original R.confirm_install/release callbacks need this path. RuntimeFlow must not synchronously block the main loop on that same worker R lock (root owns the minimal renewal change). Main callback execution must not concurrently acquire cross-owner locks in an opposite order; the shared Runtime uses one Session worker, and this adapter does not create new workers/parallel publishers.

Original F exceptions propagate unchanged, including an original checkpoint TimeoutError; they are distinct from a caller Future wait expiring. A worker wait is finite, default 30 seconds and never over 30. Timeout cancels a Future that has not begun; its queued callback checks cancellation before calling F. If F already began, timeout returns PUBLICATION_UNKNOWN and does not interrupt, retry, or duplicate the original call. Its durable original request remains F's only recovery authority. Closing/stopping a loop before a worker call rejects without enqueue.

Pre-registered finite cases:
- FT00 baseline (original FileStore, before adapter): fresh worker capture and install reject UNSUPPORTED; subsequent worker query of the original uninstalled intent returns unknown/UNSUPPORTED. Main-thread query confirms not_installed. Preserve original failure, not component acceptance.
- FT01 true R/F + original FilePublication fixture: worker capture produces exact file bytes and real main-thread lease/inotify facts; worker import remains on worker. Worker publish performs one original F exchange, R confirmation/release and complete output; repeat preserves receipts/inodes. Historical/materialize methods remain inherited.
- FT02 original existing writer FD rejects capture/installation without changing bytes/roots or releasing responsibility; removal of FD allows original identity recovery only where original F allows.
- FT03 worker within real R transaction: capture/install reject before F callback/write; query_install succeeds for original not_installed and installed layouts with no authority callback count change. No fabricated query record.
- FT04 cancelled-before-start timeout performs zero F work; already-started timeout completes the original capture once, returns unknown to caller, and subsequent original-ID lookup reuses its record. An unavailable loop/off-main bind rejects; actual checkpoint TimeoutError preserves original exception identity. Test short delegate_timeout=0.1, original default remains 30.

Only real R SQLite, F Git/files/leases plus the existing fixed X stop-source fixture are used; no Docker/model. Original X archive/stop bytes establish source provenance for this seam, not new temporary inodes having been run by X. Frozen source copy execution and real raw records retained. Parent independent acceptance follows; this author work grants no system pass.
