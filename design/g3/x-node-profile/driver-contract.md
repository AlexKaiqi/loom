# 增量独立观察与测试包装边界

当前仅冻结问题/字段/正负动作与原件要求；正式XN12场景driver尚待根确认接口后补齐和独立审查，不能把7个非Docker检查当D02完整实际driver或Node功能PASS。原X/S验证文件不修改。

测试入口应复用原X独立副本JSONL候选协议，只向候选传普通完整request/authority/profile与实际内容ref，绝不传caseID/expected/assertions。内部domain=session的caller/ref由受信配置给定；模型Shell的target=session单独从外部模型边界进入必须拒绝，不允许先把它重写成合法内部请求。禁止根驱动直接起容器替代X执行正式XN正例。只有依赖闭包准备探针可直接用固定Engine，并标PREPARATION。

每次执行前的独立inventory包括当前容器完整ID、原namespace和卷。未经授权/坏内容等负例必须对前后inventory、原执行spool和效果文件同时核对，无新增对象/无effect；仅候选code=denied不够。相同合法请求须实际Node/Pi启动，避免恒拒绝实现。观察器绑定sourcecopy、完整请求digest、profile与依赖manifest、原Engine容器/exec/volumeName+Source/原object generation。使用原S物理观察器核UID0keeper/UID1000task同隔离namespace；实际Mounts逐target精确比来源和RW=false，路径前缀文字不算授权。Node及依赖实际版本/字节从已封存manifest与真实容器只读文件重新hash；/proc/task/environ、fd、自有控制canary与网络连通反例是实际观测而非候选提供的布尔值。

每个control call/raw stdout/stderr/完整frame和write/read返回范围均保存。XN07须三个不同短peer PID，桥唯一持有原channel与原Node PID；Node从真正stdin读取随机固定种子nonce后写精确reply并追加普通JSONL。两次peer退出后第三次仍同container/exec/generation，序列与计数从原checkpoint bytes核对。XN08在实际写入后阻断ACK、杀桥，记录原namespace依然存在/后续实际kill，无新execute计数。无法恢复原attach应明确UNKNOWN/paused；不能用新process重放同文本得到相同结果。不得写“自动恢复已验”除非原回执/数据cursor具备独立反例证据。

XN09的中间checkpoint允许resume原对象；最终保持同freeze generation到actualseal。原PiJSONL必须由独立reader读取actualarchive与sourcefile逐byte/hash核对；只owner/path字符串或S回复result不算源证明。新的execution可从原S snapshot恢复只读query，不再accept/drive旧operation。F在此不发布Session为Surface；XN12用实际F较大limits处理普通输入，并逐文件原件比hash，缺/错引用拒绝。

XN11收集三主要角色完整EngineInspect及共享helper生命周期、实际volume statvfs/cgroup/output/archive/spool bytes/inodes，按最坏重叠全量相加；两个主要对象在时观察器只占预留helper，不开第四个。超限正负样本在冻结预算内完成；清理只针对本批精确创建对象，实际旧namespace为空才标stop。Root调度许可只协调Docker互斥，不改变用例判据。

原件缺失/observer失败/候选异常为INVALID或FAIL，不算负控killed。全XN通过后才可给Node增量门槛；原X28/97仍须单独通过，S27与真实模型/系统另验。
