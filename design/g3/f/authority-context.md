# Mandatory F authority context v1 (FG01/FG02 local repair)

Source obligations: F contract authorization of actual resource/domain/version/path; original X export association and exact original installation. Independent failures and unchanged old source: design/g4/f-independent-counterexamples-001 and validation/components/f/evidence/component-independent-001. Full rationale: design/g4/f-independent-interface-repair-proposal.md. Old contract/fixture/gate retained under history/authority-context-001.

Both callbacks now have three mandatory arguments: authorization_checker(value,purpose,context) and reference_checker(value,purpose,context). Exact context schema/operation fields and nested structures are in authority-context.json. These contexts carry actual observed inputs to the original trusted authority, not another permission registry. No implicit two-argument fallback, truthy non-True acceptance, exception-as-approval, or caller-token-as-own-expected-scope is permitted. Rejection uses UNAUTHORIZED / REFERENCE_INVALID and preserves original files/roots/records. The copied context is detached from mutable API inputs so authority code cannot redirect the later action.

The original F01-F19 behavior and observers are unchanged. Its broad fixture explicitly accepts/records the third argument; source-only direct fixture validity assertions pass context=None and do not count as a production authority call. The new independent FS01-FS12 supplement fixes actual scope against concrete native paths, full immutable refs, file hashes, request IDs, and actual root identities. Optional-context capture in that supplement is solely an adversarial observation of the old two-argument implementation; it intentionally records old missing-context authority calls and lets old true tokens reveal wrong-scope execution. It is not a product compatibility rule. Legacy exact-two-argument callbacks are separate explicit negative controls.

Each authority entry has positive and wrong-scope observations, including same-path wrong archive bytes, wrong base, wrong file/resource/version, wrong target, wrong capture root/revision, complete intent/stop scope and pin release. Missing/always-green module controls still cannot pass. No product implementation change is included in this preparation revision; root independently reviews the frozen preparation before repairing F.
