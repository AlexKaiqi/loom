# Capability extraction

The extraction moves source and authority, preserving schema-2 Work and loom/1
execution lineage. It does not claim implementation of the design book's Temporal /
schema-3 author API. The target contract remains in the design book.

Loom owns durable custody, input disposition, authorization, Work content and recovery.
Model Resource Hub owns native single-attempt Pi access, catalog and provider tests.
OnDemand Sandbox owns execution contracts, archive delivery, provider implementations,
prepared-process deployment and provider tests. Worksurface owns the reference
projection policy, Agent loop, initial template and strategy tests.

A driver is a host-approved deployment selected by the fixed Harness manifest. It
receives no model credentials and can only invoke host operations. A model call is
recorded before dispatch; its native result is recorded before delivery to the driver.
A lost driver response cannot authorize another upstream call. Preserve unknown
effects and original bindings throughout extraction.

Acceptance: independent package installation; real Pi loop against a controlled HTTP
peer; custody ordering; large records; refusal of unknown dispatch; provider path
reporting; isolated provider component checks. Real Linux, remote-provider and paid-model
scopes require separate current evidence. Do not infer them from component passes.
