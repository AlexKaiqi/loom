Cloudflare Sandbox Bridge

接入前先核对 Provider 公共契约与Sandbox 作者契约。

Cloudflare Sandbox Bridge

采用现成桥，不从零写云端执行网关。 官方稳定 bridge 是可部署的 Worker 模板，主体逻辑在 @cloudflare/sandbox 包中；算力由 Cloudflare Containers 承载，应用不需要使用 Workers AI。Loom 的 Go HTTP 客户端调用部署后的 HTTPS origin，不要求整个 Runtime 运行在 Worker 内。[S36]

官方 cloudflare/sandbox-sdk/bridge/worker 模板
  → 设置 SANDBOX_API_KEY（受信 secret）
  → 锁定 Worker / SDK / container image / OpenAPI
  → 用官方部署流程发布
  → Loom 配置 bridge HTTPS URL + 私有 credential_ref

Loom → HTTPS / JSON / SSE → 官方 Bridge → Sandbox SDK → Container
Loom 操作官方稳定 Bridge 接口确认与范围
Describe / 预检GET /health；GET /v1/openapi.json核对固定 API 与部署摘要；测试受保护路由缺 token 必须拒绝。官方模板未设置 SANDBOX_API_KEY 时会跳过认证，生产不得以该状态启用。
AcquirePOST /v1/sandbox → {"id":"..."}保存原创建 Effect 及返回 ID。文档未承诺 create 的幂等键或按 Loom key 查回；回执丢失保留未知，不循环 POST 创建。
InspectAllocationGET /v1/sandbox/:id/running这里只是容器 liveness，不是完整 Ready，也不是原命令状态。若所锁定组合不能证明实例世代，旧命令仍保持 unknown。
ExecutePOST /v1/sandbox/:id/exec，argv / cwd / timeout_ms；响应 SSE上游 bridge 做 argv quoting。stdout/stderr 为 base64 分块；exit 携带 exit_code；error 不是未执行证明。持久终态与流完整后才返回完整 native_result。
文件／内容GET/PUT /v1/sandbox/:id/file/*；POST .../hydrate；POST .../persist文件路径限定 /workspace；PUT/hydrate 的文档上限 32 MiB。persist/hydrate 用 tar 传输，不作为 Loom 的长期内容版本库；捕获稳定性仍须验证。
可选云存储POST .../mount、POST .../unmount复用 R2/S3 挂载。对象存储挂载不等于宿主目录 bind mount，更不能直接承诺本地 POSIX/fsync/锁语义。
ReleaseDELETE /v1/sandbox/:id → 204是销毁整个环境；必要文件应已保存。不是逐命令取消，也不是上游计费证据。
{
  "argv": [
    "python3",
    "-c",
    "print('hello')"
  ],
  "cwd": "/workspace",
  "timeout_ms": 120000
}

该接入固定官方稳定 Bridge 的 HTTP schema。逐命令 Query／Cancel 和逐请求 env／stdin 未列在参考 Bridge 表面中，对应配置不声明支持。Profile 需要缺失能力时，在分配前返回能力错误；SDK 与 HTTP 发布面分别校验。

客户端 deadline 到期或 SSE 断开不证明原任务停止；稳定 SDK 明确存在客户端超时后底层进程继续运行的情况。没有命令核对证据就保持 unknown，不用第二次 exec 取得“新结果”。只读文件／原结果可继续收集；需要停止整个分配时先核对影响范围。[S37][S40]
