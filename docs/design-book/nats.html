A.1 事件与输入的实现

本页落实事件与输入的目标契约，选用 NATS／JetStream 保存和投递事件；目标 Work 的输入及处理状态由选定持久控制组合保存。两者之间的桥接必须在目标确认受理后才确认传输完成，避免消息已被移出队列、工作却没有留下待办。

Harness 接口契约 NATS 侧 Work／Durable 侧
publish 固定 event_id、Nats-Msg-Id，PublishMsg，等 PubAck。 先保存内容和原发布请求；PubAck 后保存发布收据。回执丢失使用原身份补交。
subscribe 一个逻辑订阅一个 durable pull consumer，固定来源过滤和起点。 目标保存订阅定义、状态及 start_cursor；运行实例退出不删除它。
delivery Fetch／Next 取得消息，核验来源、内容与权限。 将事件、订阅身份及版本交给目标 Work 校验；同目标去重，并在同一次提交中登记输入及处理责任。
ACK 目标准入确认后 DoubleAck；暂时错误延迟重投。 ACK 前必须能确认原 InputReceipt；业务处理不在 ACK 等待范围内。
unsubscribe 退订之后停止拉取并清理原 consumer；残留消息不直接成为新输入。 先在目标提交关闭订阅标记，与输入准入同序仲裁；该确认成立后才返回退订成功。

来源和类型映射到 loom.v1.<scope-token>.events.<source-token>.<type-token>。token 采用确定编码，不直接拼任意名称或通配符。事件信封沿用 loom.event/1，包含 event_id、source、event_type、event_ref、observed_at；大正文在内容库，不进入 subject。

目标按“作用域＋可信来源事件＋目标 Work”去重；订阅版本、引擎运行实例标识（Run ID）和重投次数不改变该身份。匹配订阅作为单独关联保存；相同来源身份换正文为冲突。传输去重窗口不替代工作级身份记录。

订阅登记和退订的确认点

订阅登记先保存原请求，固定来源起点 L，再准备 durable consumer；在目标持久状态中激活同一 subscription_id。桥接组件只向目标交付有效订阅版本。起点一经保存即复用；准备中崩溃用原请求续办，不重新计算 now。

历史起点需要补读时，先保护实时起点和积压，再固定来源历史范围 H，补齐历史后接实时。两条路径允许重叠并去重；未覆盖的区间报告 history_gap。“now”仅以回执给出的来源游标为界，不等于任意机器的墙上时钟。

退订以目标 Work 保存关闭标记的提交为生效点。输入受理在同一次短提交中检查订阅有效性并建立关联；关闭标记已先提交时，拒绝通过该订阅新增关联。仅删除 NATS consumer 无法完成这个保证。多条路由都已失效且输入未受理时，记录明确拒绝；已受理输入保持原关联和责任。

参考组合 T 的输入桥

桥接组件使用 Temporal Go Client 调用 UpdateWorkflow，Update 名为 loom.input，等待 WorkflowUpdateStageCompleted。handler 只验证准入、重复身份、订阅有效性并入队；不运行模型、不等待业务完成。取得并核验 InputReceipt 后 ACK NATS。

update_id = H(delivery_key, payload_digest, routing_identity) 用于传输重试；业务唯一性仍由 delivery_key 决定。routing_identity 对应有效订阅关联或直接交付身份，使晚到的第二条合法路由可以进入关联校验，而不会因命中已有 Update 结果缓存而跳过关联检查。相同业务键换内容必须到达冲突检查。这是Harness 接口契约对接入的要求，并发与跨运行实例的行为仍须验证。

loom.input 的相同逻辑事件可返回原 InputReceipt，并更新合法匹配关联；不能为同一事件再次生成待处理输入。关闭 Work 后，已有键可通过受保留的最终回执查询确认；新键返回 work_closed，不自动重启执行。

配置与耐久范围

项 参考配置／约束
Stream FileStorage；LimitsPolicy；DiscardNew。不同订阅保留各自消费位置，不用 WorkQueuePolicy 表达广播。
保留 尚未完成的交付不因等待过久而被自动清理；显式配置容量，满时限制新提交。已确认可清理的传输记录与长期原文分别管理。
Consumer durable pull、AckExplicit；有界 MaxAckPending，初始可为 1；不随 Harness 启停重建。
失败 暂时错误 NakWithDelay；永久非法的消息先保存拒绝原因及原消息，再终止该交付。MaxDeliver 不等于自动死信库。
去重 Nats-Msg-Id 有限窗口；业务去重由目标输入状态和长期回执承担。
同步 严格耐久采用经版本验证的 SyncAlways／sync_interval: always；副本数与磁盘同步的故障范围分别验收。
本地部署 可内嵌官方 NATS Server，私有持久 StoreDir、进程内连接、不暴露管理端给 Harness。完整交付仍须验收。
