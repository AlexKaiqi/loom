04. Durable：推进、等待与内容

4.1 Harness 要什么

已确认的步骤不用重做；尚未完成的工作不会被遗忘；等待不需要进程活着；中断后系统知道继续、核对还是等待修复。

Durable 同时保存继续依据和必要内容。它不保证任务必定成功，也不恢复任意进程栈、Shell 内存或模型生成到一半的 token 现场。

4.2 作者怎样表达可恢复程序

入口 作者负责 运行绑定负责
受管顺序代码 用所选 SDK 定义控制流；外部观察与操作经过受管调用。 保存调用结果、等待和执行历史，重建控制位置并安排继续。
显式状态驱动 提供状态 schema 和有限推进函数，返回必要状态、下一动作或等待。 一致提交状态与后续责任，按记录再次调用驱动；无隐含闭包状态。

两者遵守相同工作契约，不承诺源码可以零修改互换。采用重放 SDK 时，不再并行维护一套手工 Round 游标。 采用显式状态时，不把唯一继续依据藏在未保存的变量中。具体接入见附录 A.3。

4.3 中断后的动作

已确认的边界 恢复行为
输入已受理，尚未执行 自动安排该输入；不依赖后来碰巧又来一条消息。
模型结果已保存，工具尚未开始 使用原模型结果与工具清单，按原操作身份续办。
部分并发项已完成 复用已完成项；其余项分别继续或核对，不重跑整个批次。
结果与产物已保存，返回回执前退出 取得原收据及内容，不再次执行命令。
已可能派发，原结果未知 查询原目的地；只有明确可重复、原生幂等或获准新尝试时才派发。
等待已登记 从已记录输入、结果和计划恢复；条件已满足则推进，否则继续等待。
代码不兼容、内容缺失或权限撤销 明确阻塞原因与修复入口，不清空原任务或伪造成功。

操作重入与新的实际尝试不同。允许重新生成的模型请求单独计费、记录 attempt；只有一个选定结果驱动后续动作。非幂等外部写入结果未知时，不因执行引擎安排重试就重发。

4.4 结果等待、时间与取消

作者动作 持久契约
operation.result(id) 等原操作的确定返回；不创建第二个操作。等待超时携带原 id，不把操作改成未执行。
inputs.next(filter) 先检查已受理匹配输入，再可靠登记等待；检查和休眠之间不能漏唤醒。
受管 sleep 第一次确认时固定到期时间；重启不重新计时。到点由共享设施推进。
timer.put/update/cancel 稳定计划 id、版本、绝对到期时间和载荷；重复登记不改期，修改须检查原版本。
operation.cancel(id) 记录取消请求；实际停止、已经发生的结果和未知费用继续独立核对。

周期默认固定锚点 origin + n × every，停机后有界补齐；合并漏期须显式配置。计划取消与本期输入受理在同一确认顺序中仲裁：本期已经受理则不能抹掉。宿主停机时不能执行，恢复后记录原到期、实际受理和处理时间。

等待答复与获得批准分开。 拒绝也是答复，应结束等待；随后 Harness 根据原请求、来源、内容版本和答案作决定。对 v7 的批准不授予 v8 的发送权。

allSettled 保留各项成功／失败；race 返回赢家不自动取消其他操作。外层程序结束前，已受理的其他操作须完成、取消核对或转交责任。

4.5 内容与历史读取

入口 输入与返回 确认边界
content.read(ref) 确定引用及可选范围 → 字节、来源、范围。 不读取同名对象的“最新版本”代替原引用。
content.save / capture 字节或稳定来源 → 内容引用。 已校验、耐久且受保留；不表示共享项目已更新。
content.apply 新内容 + 目标 + 预期基线 → 整合回执。 目标基线相符才更新；冲突不覆盖。
history.open/read/search Work、授权范围、固定游标 → 记录、覆盖范围、分页游标。 读取不执行旧工具、不消费输入；无命中不证明不存在。
view.open 必需记录范围 → 固定只读文件／SQLite 视图。 未覆盖所需范围返回 not_ready／history_gap；视图不是新权威。

保存顺序为 必要字节 → 保留保护 → 结果／状态引用提交 → 成功回执。文件存在、产生稳定版本、字节耐久、共享项目更新是不同确认。只读查询缓存可重建；原文与必要操作收据不可当缓存清理。

过去读取 Surface v12 的步骤恢复仍使用 v12；新的读取可以采用 v13。查询“当前最新 facts”是一次新观察，不因数据库叫 facts 就天然可重放。

4.6 生命周期与保留

动作 改变什么 保留什么
Archive 后续模型上下文选择。 原始记录、输入处置、等待、操作及其内容。
运行历史滚动 引擎单次执行的历史长度。 Work、回执、未处理输入、计划、未结操作和必要状态。
Work 关闭 停止新业务准入，形成最终处置。 历史与原回执；慢清理已由独立持久责任接管。
Fork 从确定基线创建新 Work。 原工作及原责任不改变；新 Work 不继承执行权、秘密或未知效果重放权。

目录导出保存资料与声明的继续状态；完整备份还须覆盖实际执行引擎状态。不能仅复制 .loom/durable.json 就创建第二个活跃执行者。历史保留范围、引擎清理期限和内容 GC 必须协调；永久可读只在相应部署验证后声明。
