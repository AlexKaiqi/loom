12. 运行与契约验收

运行管理控制工作何时接收输入、推进、暂停和关闭。验收则检查这些操作在正常运行、中断及恢复后是否仍满足前文契约；不能仅凭一次任务回答正确就判定 Runtime 可靠。

12.1 管理入口

管理动作 确认语义
注册／启动 Work 固定工作身份、配置、授权、预算及初始输入，受理初始 Harness 调用并保存其实际代码和执行绑定；重复请求取得原结果。
启动／查询／取消 Harness 调用 在获准 Work 内使用 harness.start/result/inspect/cancel；启动固定原调用，查询返回原 run_id 的真实状态，取消明确本调用或同 Work 调用树范围。子调用不自动取得更多授权、预算或输入处置权。
查询 返回生命周期、所属 Harness 调用、未处理输入、在途操作、等待、预算和内容引用；离线视图注明已覆盖的记录位置和更新时间。
暂停／继续 暂停新业务推进，仍保存输入和真实结果；继续原责任。已发生的操作和结果保持原记录。
关闭 进入 closing 后，所有所属调用停止新业务意图；处置输入和计划，完成／取消核对／转交 Harness 调用、操作与清理后关闭。原回执、未知效果和迟到结果继续保留。
Fork 新身份、新授权检查、确定来源；不删除原工作或继承未知操作重放权。

Runtime 启动先验证存储、部署与能力绑定，再恢复所有未结调用、操作和订阅；停机先停止新的派发，保存／交接在途责任。Work 存在期间不要求专属进程常驻；Harness 的持续等待由共享持久内核保存，运行时按需装载原版本。多节点接管、断电与存储丢失需分别声明支持范围。

12.2 可执行判据

编号 测试轨迹 必须观察到的结果
E01 登记订阅，卸载 Harness，期间发布，再恢复。 同一订阅保留原起点，目标自动取得事件。
E02 事件先到、next 后调用；或检查空队列与休眠之间到达。 不漏输入，不需第二条消息触发。
E03 重投、两份重叠订阅、两个不同 Work。 同 Work 一个输入，不同 Work 各一个；改内容冲突。
E04 next 后退出；发布结果后、complete 前退出。 继续原输入处理，复用原发布回执，不生成第二份报告事件。
E05 退订与交付竞争，退订后仍有排队输入。 按目标 Work 的提交顺序判断；保留已受理项，排空后结束等待。
E06 起点过期、内容缺失、撤权、过载。 明确拒绝或等待及证据，无静默跳过和假成功。
D01 输入已确认、执行前退出。 自动继续，不靠用户逐项运维。
D02 结果／内容已保存、回执丢失。 取得原收据，不重做已确认操作。
D03 外部可能成功但无回执；取消后有迟到结果。 原对象核对；取消、停止与结果各自保存。
D04 定时到期、提前答复、跨运行历史滚动。 等待不丢；拒绝结束等待但不授权动作。
D05 Archive 保存中退出；旧批准遇到新内容版本。 归档选择与对应工具结果同时生效或均不生效；旧批准不用于新版本。
M01 无 Agent loop 直接批量调用；37/100 完成后退出。 独立结果和上下文，按原评审项标识接续。
M02 并发逼近预算、用量未知、schema 不支持。 原子准入、未知不当零、不静默降级。
S01 shared／transfer；Shell 退出但后代仍写；释放失败。 稳定内容才确认，阻止冲突写入，清理不覆盖结果。
S02 执行获准的文件操作；再请求越界路径、未获准网络或超出资源限制的操作。 获准操作返回实际结果；越界操作被拒绝，受保护资源未被修改，不回退到不受限执行。
S03 Sandbox 派发后通信中断；公开检查点保存失败，或产物已接管但确认丢失；期间改变当前 Profile。 Loom 保存原 Operation 与绑定，先耐久保存再确认交接；恢复仍查询原任务，重复接管复用原回执。唯一必要产物在确认前保留，未知时不改后端重放。
S04 一次普通命令要求输入文件、稳定产物和清理；另在保持公开契约的前提下更换 Sandbox 内部后端实现。 Loom 只调用完整任务能力并接管公开结果，不导入供应商 SDK 或组装准备／冻结／导出／销毁。Sandbox 独立验收完整交付，Loom 验收授权、记录、内容与恢复的接合；内部变化不要求消费侧重写这些步骤。
S05 Agent 用 Bash 写入文件，确认结果后读取／测试它；在两次调用之间重建环境；另在同一环境先运行 cd/export 再执行第二条独立命令。 下一条使用前次已确认内容，重建后不退回旧基线；独立命令使用本次固定 cwd/env，不继承前次 Shell 状态。仅声明环境会话不能标成支持持久 Shell／PTY。
H01 Basic 换 Worksurface、增加验证或更换版本。 只改对应策略；共享输入、操作和恢复契约保持。
H02 同一 Work 的 A 通过模型生成 B 并启动，B 启动 C；分别采用受管顺序代码和显式状态形式，让 A、B 进入纯等待，再恢复。 三个稳定调用身份与原代码、依赖、SDK、执行绑定可查；预授权隔离环境内可运行生成代码，无需逐次人工发布。纯等待不保留专属进程、模型连接或闲置环境，条件满足后自动继续；不要求把顺序代码改成手写状态机。
H03 B 已受理而启动回执丢失，A 重启重试原键；再以原键改代码或调用输入。 重试取得原 run_id 与原启动回执，只有一个 B；同键改内容返回 identity_conflict，不得按最新候选代码创建第二次调用。
H04 B 对固定 100 项启动 C，37 项结果已保存后退出；C 内部另在模型返回、工具开始前中断。 复用已完成 37 项及对应 C，未完成项按原调用／操作分别继续或核对；C 复用原模型结果，不重跑整批或整个模型工具循环。
H05 A／B 等待期间修改同名源码、依赖与环境配置；再撤销原权限或使原依赖不可取得。 恢复装载原代码和原绑定，新版本只用于新调用；缺失或撤权返回可修复的阻塞原因，不覆盖状态、不使用最新版本或降级到不受限执行。
H06 B 请求越权资源／额外预算，试图抢取 A 的 Work 输入；随后以原 processing_ref 显式交接，再让 A 使用已失效的处置权。 子调用不自动扩权或另获预算，默认只读固定调用输入；交接有唯一有效承接者且可恢复，A 的旧处置权不能重复完成输入。进入共享受信 Worker 或提升权限按授权规则批准。
H07 等待超时／race 后 B、C 尚未结；取消 self 与 tree，再让 Work 关闭与 B 新启动、原操作迟到结果竞争。 超时／race 不自动取消，父调用结清前完成等待、取消核对或确认转交；Runtime 接管后可返回业务结果，但未结责任与承接回执必须保留。取消范围可查且不默认关闭独立子 Work。按提交顺序阻止 closing 后的新意图，原操作、未知结果与费用继续核对，不因父进程退出或收到取消回执假报关闭。
H08 A 等待 B、B 等待 C，释放执行进程后继续增加调用，超出 Work／祖先上限或绝对深度；另请求不相容的持久控制绑定。 等待仍占逻辑调用名额，根深度为 0，子调用不能重置祖先上限；超限返回 call_limit_exceeded，不相容绑定返回 unsupported_binding，受理前拒绝不留第二份调用责任。同 Work 的受理、交接、取消与关闭保持一个控制提交顺序。
G01 把 A→B→C 与操作／内容关系构图，折叠、展开结构并改变布局。 原记录身份与边关系不丢失，折叠结构可追到成员与跨结构关系；展示交互不改变执行状态或调用责任。
G02 Harness 按两个版本的规则识别、命名相同运行记录中的结构，并加入推导或解释。 图保留固定记录范围、结构定义版本及事实来源；原始事实与 Harness 解释可分辨、可追溯，同名结构不成为权限或运行状态的额外权威。
G03 展示连接断开期间继续执行；恢复时旧范围不可增量读取，且部分操作结果未知。 明确已覆盖位置、缺口和未知状态，按新授权快照重新构图后追上；不漏报成完成，不靠展示连接存活才能提交业务结果。

12.3 证据范围

状态模型检查、组件测试、真实组件组合和产品验收分别报告。每份报告注明源码版本、依赖、配置、运行时间和覆盖的故障场景；失败、跳过或未运行的项目不能计为通过。接口映射说明如何接入，不能证明接入已满足契约。

参考模型的检查结论只适用于它覆盖的假设与状态转移。Sandbox 负责实际隔离、稳定来源、执行停止和物理清理的组件证据；Loom 核对公开版本及这些前提，并验收 Work 授权、原 Operation、检查点、内容接管和恢复的组合。S01／S02 的实际环境证据由 Sandbox 提供，不能由消费记录或替身代偿。报告和文档检查要求见附录 B.4。
