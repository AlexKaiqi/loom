A.4 Sandbox 调用与工作接合

本页定义 Loom 如何消费独立的 Sandbox 能力：将模型工具参数固定成 Work 的原请求，绑定授权和预算，调用完整执行能力，保存公开检查点并接管结果及产物。Sandbox 的目标契约、后端配置和接口由该仓库维护；目标材料为 docs/user-environment.md 与 docs/backend-reference.md。Loom 不另定义 Provider、不导入后端 SDK，也不组装环境准备、稳定化、传输和清理流程。

Sandbox 持有实际执行域、原生命令、文件交付与清理状态；Loom 持有消费侧 Operation、授权和继续依据。公开检查点与结果是二者的交接证据，不能把同一份本地 journal 变成两套 Work 控制权。选定 Sandbox 公开版本不能表达必需要求或尚未通过接合验收时返回 not_ready，不以当前实现反向降低目标。

从模型工具到 Sandbox 调用

模型可见的 bash 示例见第 6 章。Harness 注册工具说明和参数 schema；收到原模型响应中的 tool call 后，根据原模型操作及 tool call 身份固定这次工具操作，验证业务参数，将 command 作为获准 Bash 的字面输入转换为 Exec 请求，并补齐已声明的默认值。相同逻辑调用恢复时复用原键，不能重取一个键再执行。

工具适配调用 execution.submit，取得原 Operation，再通过 execution.result 等待结果或 execution.inspect/cancel 处理原执行。Runtime 按本页固定授权、预算、Sandbox Binding 及文件版本；Sandbox 的公开 SDK／CLI 接合只存在于受信执行路径中，模型不直接操作部署或供应商 SDK。连续调用的文件版本及会话／终端区别由第 6 章定义。

模型需要输出、真实执行状态及必要产物信息；Harness 可以返回摘要或流式预览，Runtime 仍保存完整结果及缺口。流式输出是否可用随公开能力判断，流式输出本身不意味着存在 PTY。后续模型请求采用已保存工具结果；结果确认丢失时回取原结果，不重新运行命令。

A.4.1 模型工具参数：tool.exec/1

模型只提供命令、逻辑 Target 和获准资源内的位置等业务参数。Bash 桥明确把 command 作为指定 Shell 程序的输入；通用 Exec 使用 argv，不隐式经过 Shell。Loom 保存原业务请求，并把参数转换为所选 Sandbox 的公开任务格式；后端仅支持字符串时的 Shell 参数引用、实际 Bash 路径和启动文件安全由 Sandbox 接合验证，不能靠未经验证的字符串拼接执行。

{
  "schema_version": 1,
  "argv": [
    "python3",
    "tools/build_card.py"
  ],
  "cwd": {
    "alias": "app",
    "path": "."
  },
  "env": {},
  "stdin_ref": null,
  "timeout_ms": "120000",
  "capture_limit_bytes": "8388608"
}
字段Loom 工具语义与消费检查
argv非空字符串数组，首项非空，不允许 NUL。原样表达程序参数；适配到不同执行方式时不修改业务身份。包含 Shell 语法的工具必须明确选择 Shell。
cwd授权资源别名和根内相对路径；. 是该执行根。拒绝绝对路径、NUL 和 .. 路径段；Sandbox 仍须在实际执行域核验软链及根范围，不以字符串检查代替物理限制。
env / stdin_ref仅传经授权的非秘密业务变量，默认空，不继承管理环境或调试注入。stdin 使用已授权的固定字节；null 表示空输入并关闭 stdin。Sandbox 凭据不进入载荷。
timeout_ms正十进制字符串，是任务执行期限；Loom 按 Work／Target 要求固定，Sandbox 按公开能力验证和落实。RPC 等待超时独立表达，不能当作原任务已停止。
capture_limit_bytesstdout/stderr 合计捕获上限，示例 8 MiB 不是默认保证。上限处置与停止要求交给 Sandbox；保留已得字节及缺口，不能标完整输出。模型预览由 Harness 控制。
模式此工具 v1 表达非交互前台任务，不打开 TTY；后台服务、端口或长会话必须使用已声明的公开会话能力，不能靠命令中的后台符号逃离责任。

tool.exec/1 是 Loom 模型工具的业务载荷，不是 Sandbox 的执行协议；Sandbox 公开请求与返回格式随所绑定版本维护。

A.4.2 Work 授权、原 Operation 与固定目的地

Loom 将逻辑 Target 解析为获准 Sandbox 入口、确定公开版本和非秘密 Binding，并固定获准文件来源、基线、实际要求及预算。Sandbox 的配置与参数语义由 Sandbox 负责；Loom 保存原目的地的公开绑定快照或引用，不读取或维护后端私有 options。凭据在受信侧按服务注入，不写 Work、检查点或任务环境。

派发前先保存有效请求、原 Operation 及执行责任，按当前授权核验本次消费范围和预算。请求中自报的目录、环境、Work 或 fence 不授权限。以下是 Loom 内部 loom/2 封装，work_id、round_id 和 operation_id 用于工作关联；Work 身份与所有权从受信连接确认，不把这些字段作为 Sandbox 必须理解的业务概念。

{
  "jsonrpc": "2.0",
  "id": "rpc-42",
  "method": "effect.request",
  "params": {
    "protocol_version": "loom/2",
    "schema_version": 1,
    "request_key": "work-card/input/42/step/12/tool/2",
    "kind": "tool.exec",
    "environment": "sandbox",
    "target": "default",
    "payload_ref": {
      "sha256": "09ec641743c97103cdf2e88f46e43efee2983e3246c705d277c3b31334e2f354",
      "size_bytes": "174",
      "media_type": "application/json"
    },
    "work_id": "work-card",
    "round_id": "work-card/input/42",
    "operation_id": "work-card/input/42/step/12/tool/2"
  }
}

普通工具把命令和文件要求交给 Sandbox 的完整任务入口，不先向后端创建环境再自行调用 Execute。申请、文件准备、实际执行、稳定产物和资源结束由 Sandbox 维护；消费侧只保存公开交接。需要会话时，固定该公开会话的原引用及有效范围，不授予其他 Work 或新命令权限。

A.4.3 公开检查点与执行接管

Sandbox 的公开 TaskExecutor 或会话入口交付任务结果及恢复证据；具体请求字段以所绑定公开版本为准，不要求 Loom 导入 Provider 私有接口。消费接合将原 Operation 身份关联到该任务请求，固定实际 Binding；查询、取消和归还始终引用原公开对象，不按当前 Profile 重新路由。

采用 TaskExecutor.Execute 的公开 Checkpoint 回调时，Loom 先核验检查点属于原请求及绑定，保存相应原生关联、阶段、Readiness、输出/产物引用和必要字节，并完成耐久确认，再向回调返回成功。保存失败必须返回失败，由 Sandbox 按其公开契约停止继续该交接或保留原执行与清理责任；不能先确认，再异步补 journal。

消费 journal 记录 Sandbox 已交付的公开检查点，供 Loom 恢复原 Operation 和重取原对象；它不解释后端私有阶段、不自行决定创建/启动/导出步骤，也不替代 Sandbox 对实际状态的查询。相同交接重复时核对原证据并复用，冲突不覆盖已有记录。尚未取得原生 id 时仍保留已派发记录，不能把空 id 当作未创建或未运行。

客户端通信成功、Checkpoint 已保存、原任务终态和 Work 已接管内容是不同确认。Sandbox 若只交付包装进程或连接结果，Loom 不将其提升为任务结果；组合须提供真实结果范围、完整性及缺失状态，能力不足时拒绝对应保证。

A.4.4 结果、稳定产物与接管确认

Sandbox 交付Loom 确认失败时保留
原命令的结果、输出、用量/费用观测及范围核验原请求，保存实际退出/信号、输出流 separate/combined、完整性与原文。非零退出仍保存为已知结果，业务判断留给 Harness。部分输出、已知结果、缺口与费用未知；通信错误不改写为任务退出。
稳定产物或可读取的稳定来源、范围、摘要和保留条件经 Content 入口校验字节，耐久保存并建立受保护引用；完成接管后才给出内容交接确认。Sandbox 的原产物/来源及交付责任；不得提前销毁唯一必要字节。
资源使用、停止和清理结果保存原对象证据；已接管内容对应的保留条件满足后，确认允许后续结束/清理。原查询/取消/清理身份及剩余责任；不覆盖业务结果，不推定费用为零。

Sandbox 在完整任务能力内取得稳定来源、协调必要冻结/快照/停止及文件交付；Loom 不再选择私有 Stabilize／Resume／Export 调用顺序。shared 和 transfer 的实际读取/传输必须随 Sandbox 的公开交付保证核验，HTTP 成功、相同摘要或挂载存在都不能单独证明内容稳定或已持久接管。

接管顺序是取得可验证字节 → 校验及耐久保存 → 保护内容引用 → 提交原 Operation 的结果/交付记录 → 确认接管。确认通过绑定版本的公开 sink、回调或交付回执表达，不自行发明后端私有 ACK。Sandbox 已把字节交给经确认的持久 sink 时可据该证明清理；没有接管证明时必须保留原来源或明确未满足条件。

content_delivery=confirmed 只表示 Loom 已完成相应内容接管和版本提交，不是 Sandbox 上传成功或原任务已退出。共享项目整合继续通过 content.apply 的预期基线校验完成；执行副本的产物保存不直接更新用户项目。

A.4.5 原请求查询、取消与 Work 关闭

重启先读取原 Operation、公开 Binding 和 Checkpoint。已确认结果直接复用；可能已派发则通过原 Query／会话查询入口核对，缺少原生身份或不支持查询时保持 unknown。只读核对不启动、重建或重做原任务；对环境进行 resume、续期等变更需按公开语义另受理。

取消先保存原 Operation 的取消责任，再通过 Cancel／公开会话入口请求停止原任务及授权后代。只有整会话停止能力时，Sandbox 明确返回影响范围，Loom 核对独占性及 Work 授权；不能暗中停止共享环境中的其他任务。原生停止、可能已发生的结果、费用和资源删除分别确认。

closing 拒绝新的业务意图，但允许核对原对象、接收迟到结果、接管必要字节和处理清理。必要内容受保护后，Sandbox 的原资源释放经公开 Release 或对应会话入口处理。Loom 可将消费侧剩余核对任务交给独立持久承接者，取得承接回执后让原 Harness 结束；承接者仍调用 Sandbox 查询原状态，不复制另一份执行控制。

Sandbox 的实际未释放状态和 Loom 的未结责任必须同时可查询。客户端关闭、Work 引擎终态和单次 Release 返回不能替代相应公开资源/停止保证；失败分别报告，独立 Userspace 不随清理删除。

A.4.6 workspace.access/1：消费侧文件映射

userspace.binding/1 维护 Loom 的逻辑资源、授权与基线；workspace.access/1 将这些根关联到 Sandbox 对原任务/会话交付的公开执行路径。路径从实际能力回执取得，不由 Loom 推断镜像、挂载或供应商目录，也不由模型提供宿主路径。

映射信息消费语义
原环境关联v1 的 allocation_id 与 binding_generation 是消费侧对原公开任务/会话环境的固定关联；同时保留原 Sandbox Binding 与来源回执。它们不授予后端管理权，不要求作者先自行分配环境。
获准根roots 保存 alias / working_copy_id / access / base_ref / scope_ref，匹配原 Userspace 授权。只向作者提供其可用范围，不发布管理路径或凭据。
执行路径execution_root 来自 Sandbox 原任务/会话的公开文件映射，只在该对象与世代内有效，不当作可移植资源身份。Sandbox 验证实际根及软链限制，Loom 根据别名和根内相对路径选择获准资源。
内容方式content_mode 的 shared/transfer 记录该次已固定交付方式。Sandbox 落实共享访问或完整传输；Loom 按公开来源取得并接管内容。失败不静默改变方式或目的地。

物理 storage locator、根句柄、挂载和文件服务凭据归 Sandbox 的宿主配置与实现；Loom 仅通过公开资源/文件契约传递获准来源及范围。可写请求默认要求保存必要变更，不凭模型说“只读”降低保证；纯只读或无产物操作可记录 content_delivery=not_required，须有真实授权与要求依据。

旧 Provider 材料的权威归属

原 sandbox.provider/2 的 Provider 接口、能力 Descriptor、后端 DTO 与配置 schema 已移归 Sandbox，定义见 docs/backend-contract.md，后端入口见 docs/backend-reference.md。Loom 不继续维护第二份定义，也不把它们作为自己的消费接口；当前绑定是否满足用户环境要求，以所固定 Sandbox 公开版本和验证报告判断。

Provider 内部接口由 Sandbox 的 docs/backend-contract.md 维护。
