A.4 Provider 类型与命令载荷

以下保留 sandbox.provider/2、sandbox.exec/1 和 workspace.access/1 的具体操作、字段及 schema。它们描述内部适配协议，任务模型只填写工具的业务参数。内部 round_id／epoch 等运行字段由所选绑定提供，不要求普通批量推理程序维护 Basic 的回合游标。

命令载荷：字段、路径、超时与输出

参考工具形状为 bash(environment="sandbox", target="backend", command="…", cwd={alias:"app", path:"."})。Bash 桥使用该环境已确认的 Bash 路径，转换为 argv=[bash, "--noprofile", "--norc", "-c", command]；通用 Exec 则直接执行 argv，不隐式经过 Shell。以下规范化载荷保存在 payload_ref 中；仅 command/target 等业务参数需要模型提供，默认值由桥和宿主要求补齐并固定。

{
  "schema_version": 1,
  "argv": [
    "python3",
    "tools/build_card.py"
  ],
  "cwd": {
    "alias": "app",
    "path": "."
  },
  "env": {},
  "stdin_ref": null,
  "timeout_ms": "120000",
  "capture_limit_bytes": "8388608"
}
字段固定语义
argv非空字符串数组；首项非空，不允许 NUL。直接传给执行设施；不拼接成宿主 Shell 字符串。包含 Bash 语法时由桥明确选择 Bash。
cwd必需的授权资源别名和根内相对路径。. 指向绑定的执行根。拒绝绝对路径、NUL、.. 路径段及实际根外解析；字符串校验之后仍检查软链与物理授权范围。本 v1 只覆盖具备文件工作副本的任务。
env / stdin_refenv 为经授权的非秘密业务变量，默认空；不自动继承 HOME、代理／调试注入或管理环境变量。stdin_ref 为已授权原始字节引用，null 表示空输入并关闭 stdin。Provider 凭据不在载荷中。
timeout_ms正十进制字符串。桥从 Profile 和宿主上限取允许值并写入请求；它是执行超时，不是 RPC 等待超时。实现不能落实相应超时／停止语义时，在派发前拒绝。超时后是否停止仍需原生证据。
capture_limit_bytesstdout 与 stderr 合计的完整捕获上限；本例为 8 MiB，仅是示例配置，不是全局默认。超过时请求停止，保留已得字节和 output_limit 诊断，不能标记完整输出。面向模型的预览／分页另受第 7 章有界呈现规则约束。
执行模式v1 只提供非交互前台执行，不打开 TTY。不得把命令中的后台进程视为独立已登记任务；需要 async、TTY、长服务或端口会话时，须另行协商其生命周期能力。一个活跃 Allocation 内可顺序运行多条命令。

公开操作params 必需字段返回的最小字段
allocation.acquirerequest_key, target；Profile 和资源要求从本 Work 的确定配置取得，不接受模型覆盖管理 options。allocation_id, effect_id, accepted_fact_id, observation_ref；最后一项可为 null，表示还没有就绪观察。申请身份先分配并持久保存，原生资源 ID 可以晚到。
allocation.inspectallocation_id；只查询原申请／原分配。allocation_id, provider_binding_ref, observation_ref, workspace_access_ref；未知项为 null。原生状态、每项能力与证据通过观察记录读取。
allocation.releaserequest_key, allocation_id；提出结束本次使用，不授权删除 Userspace。effect_id, accepted_fact_id；后续按该 Effect 查询实际归还。是否删除底层专属对象由受信保留／清理规则决定。
effect.inspect / cancelinspect：effect_id。cancel：request_key, effect_id；绑定原对象，不要求调用者再提供当前 target。inspect 返回第 E 部分的当前观察与引用；cancel 返回原 effect_id, accepted_fact_id，仅说明取消请求已保存。首次取消已确认后重复请求返回同一回执。

Provider 核心、可选接口、DTO 与能力 Schema

sandbox.provider/2 是 Loom 内部适配契约。共同核心提供资源描述、取得、查询和归还；执行、命令查询、停止、稳定内容与传输分别协商。所有变更经过原操作身份与新鲜派发许可；只读查询不会重新执行原动作。能力描述覆盖完整适配组合，包括提供稳定来源或停止证据的执行及内容组件。

操作／能力输入输出与必要约束
Describe · 核心固定的 Provider／service 绑定兼容接口版本、宿主/执行平台范围、可用操作与限制；只报告能力，不运行用户代码，不授权。
Acquire · 核心申请 Effect、原 key、已选 Profile、获准根与资源绑定Allocation 的原生关联、workspace access 与实际能力证据；已接受、已创建和 Ready 分开。
InspectAllocation · 核心原 scope/key/Allocation；已知时带 native resource reffound／not_found／unknown；查询未找到不单独证明从未创建。
Release · 核心原分配、归还 Effect、释放范围与内容保留依据使用结束、执行隔离、对象删除分别确认；不删除 Userspace。
Execute · exec/1原 Effect／Allocation，argv、解析的 cwd/env/stdin 和预算原生观察与流；结果注明 task／wrapper／transport 范围，不能混成一个 exit code。
InspectExecution · exec.query/1原命令身份及对应调用绑定只取原操作状态／可重取字节；不支持时暴露能力缺失，已有本地记录仍可读取。
StopExecution · exec.stop/1取消 Effect、原执行对象、已授权停止范围返回停止请求及实际证据。仅能停止整个 Allocation 时，须明确返回该范围，由 Runtime 判断是否允许，不能暗中扩大取消。
Stabilize · content.stable/1明确副本范围、要求的 frozen／snapshot／stopped 方式返回实际可读取的稳定来源和覆盖范围；shared 来源可由宿主执行组件与 ContentPort 共同提供。来源方式、句柄和证据必须相符。
Resume · content.resume/1原分配与原 hold_ref仅解除原冻结；只有声明 frozen 的组合必须提供，不要求所有 VM 有冻结功能。
ImportContent / ExportContent · content.transfer/1确定内容或稳定来源，原副本与预期基线传输回执和完整性；shared 不调用，不能为接口对称加一次复制。
type Provider interface {
    Describe(context.Context) (ProviderDescriptor, error)
    Acquire(context.Context, AcquireRequest) (AllocationObservation, error)
    InspectAllocation(context.Context, AllocationQuery) (AllocationObservation, error)
    Release(context.Context, ReleaseRequest) (ReleaseObservation, error)
}

// Independent optional interfaces; the descriptor declares tested constraints.
type Executor interface {
    Execute(context.Context, ExecRequest, ObservationSink) (ExecutionObservation, error)
}
type ExecutionInspector interface {
    InspectExecution(context.Context, ExecutionQuery) (ExecutionObservation, error)
}
type ExecutionStopper interface {
    StopExecution(context.Context, StopRequest) (ExecutionObservation, error)
}
type StableContentProvider interface {
    Stabilize(context.Context, StabilizeRequest) (StableSource, error)
}
type ContentResumer interface {
    Resume(context.Context, ResumeRequest) (ResumeObservation, error)
}
type TransferProvider interface {
    ImportContent(context.Context, ContentImport) (TransferObservation, error)
    ExportContent(context.Context, ContentExport, ContentSink) (TransferObservation, error)
}

这些接口不提供 RunAgent(prompt)、计划解释、业务完成或账本写入口。稳定内容和传输为可选能力，但声明可写文件且承诺 per-tool 保存的 Profile 必须具备一条真实可用的稳定读取路线。Loom 的内容库统一写 Git 与 records；Provider 只提供稳定来源或传输，不各自建设第二套文件版本库。 Execute 的前台超时约束由该锁定后端实际实现；可选 exec.stop/1 指另外发起取消所需的接口，不免除已经承诺的超时与清理责任。

类型最小字段与约束
公共操作绑定schema_version=1、operation_id（已有 Effect ID）、work_id / round_id / epoch、allocation_id / binding_generation、provider_binding_ref、原请求引用。Describe 和只读查询不要求新的 operation_id。有效身份来自受信调用与 Runtime，不信任任务自报。
AcquireRequest / AllocationQueryAcquireRequest：公共调用绑定 + 预分配的 allocation_id/binding_generation、request_key、target、profile_ref、provider_binding_ref、userspace_bindings_ref、requirements、trusted_roots。requirements 固定所需能力；trusted_roots 是宿主核验后的物理资源句柄集合，不由任务填写。AllocationQuery：原 provider_binding_ref、allocation_id、binding_generation、原 request_key，及可为空的 native_resource_ref；不传新的目标定义。
ExecutionQuery / StopRequest查询包含原 effect_id、allocation_id、binding_generation、provider_binding_ref 和 nullable native_execution_ref；没有原生 ID 时按该后端声明的 request_key 核对。StopRequest 另带取消责任 operation_id 与请求范围，不另造 command；目标只能是原执行及它的受管后代，不能因无命令级停止能力而误停共享环境中的其他任务。
ReleaseRequest原分配绑定 + operation_id + disposition（end_usage 或 destroy）+ retention_clearance_ref。end_usage 结束本次使用；随后删除保留的专属对象，用 disposition=destroy 和独立清理 Effect。清理许可绑定明确内容保留及身份；上游释放不可避免地删除对象时，必须在调用前满足对应保留条件，否则拒绝销毁。对外 allocation.release 不直接授予模型修改这些管理字段的权限。
StabilizeRequest / ResumeRequestStabilizeRequest：原分配、operation_id、working_copy_id、scope_ref、expected_base_ref、mode（frozen/snapshot/stopped）。后端不得静默换 mode。ResumeRequest：原分配、operation_id、hold_ref；只解除同一冻结，不启动新的任务。ResumeObservation：resumed/not_applicable/unknown + 原 hold_ref 与证据；快照或已停来源不用伪造一次 Resume。
ContentImport / ContentExport公共绑定 + working_copy_id、scope_ref、expected_base_ref。Import 提供 source_content_ref；Export 提供 stable_source_ref。字节经过受信内容源／sink，临时路径限于适配器内部。传输请求与结果保存到 Effect／records。
ProviderDescriptorinterface_version="sandbox.provider/2"、provider、capabilities（name/version/constraints）；platform_pairs 每项声明 host_os、execution_os 与 architecture_relation（native/declared_by_allocation）；按组合校验，不把两个 OS 列表作笛卡尔积，location 为 local/remote；content_modes 为 shared/transfer；网络规则与停止/硬配额的真实范围见 constraints。query_by_request_key、execution_lookup（native_id/request_key/none）、result_retention（scope/expiry/可否重取）、disconnect_behavior（continues/stops/unknown）均不可缺省推成支持。描述特定锁定组合，而非整个品牌永久能力。
AllocationObservationrequest_key / allocation_id / binding_generation、provider_binding_ref、nullable native_resource_ref、resource_state（creating/running/stopped/missing/unknown）、capability_observations、workspace_access_ref、observed_at / evidence_refs。未知/未支持明确表达；资源存在并不表示任一能力 Ready。
ExecRequest公共绑定 + payload_ref、解析后的 argv/cwd/env/stdin、workspace_access_ref、实际预算；派发由当前受信调用授权，不把可缓存的布尔许可作为字段。原生执行引用取得后追加绑定，不回写旧请求。
ExecutionObservation原 Effect／Allocation／native execution ref，observed_at、evidence_refs、原生状态与输出；outcome_scope 必需为 task/wrapper/transport。exit(code) 与 signal 分别表达；超时、失联只是观测原因。wrapper 或 transport 退出不能直接结算 task 成功，只有对应后端明确保证等价并保存证据才能映射。保留 partial 输出，缺少完整流或终态不确认完整 native_result。
StableSourceworking_copy_id、scope_ref、mode（frozen/snapshot/stopped）、stable_source_ref、evidence_refs、nullable hold_ref；只证明本次范围可稳定读取。freeze 申请与恢复由已有责任保护，失败保持阻塞，不作为普通临时缓存。
TransferObservation原导入/导出 Effect、源引用、目标副本及范围、字节摘要、完整性、原生回执引用。Loom 完成内容耐久和版本提交后才形成 content_delivery=confirmed，不能把上传 HTTP 200 当内容版本已确认。
ReleaseObservation原 Allocation；usage（held/ended/unknown）、execution（active/fenced/unknown）、resource（retained/removed/unknown）、原生计费观测（可未知）与 evidence_refs。若有已登记独立清理责任，Harness 无需为清理常驻。

稳定来源必须支持捕获方的实际读取路径。暂停环境会同时停止其文件服务时，须采用可用的快照或共享存储读取。容器 rootfs 导出不包括未经验证的挂载副本快照。要求 per-tool 保存的可写 Profile 必须具备稳定读取能力，否则拒绝该配置。

workspace.access/1：shared 与 transfer

userspace.binding/1 保存逻辑资源、授权和基线；workspace.access/1 记录相应执行路径及 shared／transfer 方式。Runtime 在获准的 allocation.inspect 回执中提供任务可用路径，管理路径、密钥和挂载句柄仅在受信侧使用。

字段类型与语义
记录头schema_version=1、allocation_id、binding_generation、userspace_bindings_ref；roots 为根映射数组。
每个根alias / working_copy_id / access（read/write）、content_mode（shared/transfer）、execution_root、base_ref、scope_ref。其中身份和范围必须与原 userspace 绑定匹配。
execution_root本执行环境内的实际绝对路径；local 模式是已授权真实宿主路径，Linux VM 可以是 /workspace。路径只在该 Allocation 内有效，不作为可移植资源身份。发布给模型前过滤未获准根。
content_mode=shared执行域与获准持久存储使用同一份副本（直接使用、bind mount 或经验证的持久卷）。不调用内容导入/导出；仍需稳定来源与版本确认。
content_mode=transfer运行期文件位于不能共享的任务存储。先导入确定基线，后从稳定来源导出；必要文件未确认前不能按临时盘策略销毁。
受信物理绑定真实 storage_scope、存储 locator／根句柄、路径规范化证据、挂载参数、共享卷与访问凭据由宿主解析。不得用模型提供的目录名、软链或环境名绕过根范围；远程 Provider 不能把控制主机路径当自己的 hostPath。

同一个 Profile 可以选择一种已支持内容方式，但不可在某次传输失败后静默切换；方式、路径和副本绑定在 Allocation 中固定，重新分配另留新绑定。可写请求默认按可能修改必要文件处理，不依赖模型说“只读”降低保存要求。纯只读资源或无文件操作可返回 content_delivery=not_required，需有真实授权依据。
