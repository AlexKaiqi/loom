10. 图结构与展示

Harness 可以把运行记录、内容与当前理解组织成图，定义哪些节点和关系构成一种结构，再为它命名、描述并展示。图结构的含义随 Harness 或专用语义适配器维护；Loom 无需先把所有可能的组织方式列为 Runtime 实体。通用图展示复用 graph，不另建 Harness 专用图前端。

10.1 运行事实、结构含义与展示

责任方交付确认边界
Runtime按授权读取的原记录、固定内容引用与记录覆盖范围。原记录描述实际受理、尝试、结果或未知；不会因节点标签或连接线而改变操作状态、权限及责任。
Harness／语义适配器映射规则、结构定义、确定版本的图快照与依据。说明图中每种关系与结构的含义，区分观测、推导和未知；采集、映射和递送是 Loom 的接合工作。
graph节点、边、结构集合的通用展示，以及描述、布局、折叠、展开和导出。校验通用图结构并保留原身份及连接；不理解业务标签，不自动采集 Runtime，不验证领域关系。

图是带来源的表达，不成为第二份执行状态库。坐标、参考线、显示行和折叠形状不独立证明时间、因果、权限或完成。展示“已完成”必须能定位实际结果记录；发布图快照只确认内容已保存与通知责任已受理。

图工作台的准确格式、入口与限制以其公开契约为准。这里定义 Loom 的来源信封与接合要求，坐标、端口、投影映射、几何与挂载限制直接引用该契约，不另维护副本。

10.2 定义与命名图结构

结构定义作为 Harness 版本材料保存，固定节点映射、边的含义、候选结构的判定范围、命名和描述方式。例如，一份 Harness 可将获准的调用记录映射为节点，将两次调用之间的已记录操作映射为边，再把满足某规则的节点集合命名为一段评审结构。这样的名称属于该定义，不要求 Runtime 或图工作台新增同名实体。

一份定义必须说明：需要哪些原记录或内容、如何形成稳定 ID、怎样区分直接记录与推导关系、缺少输入时返回什么未知项，以及版本变化如何影响原结构。自动识别由 Harness 或已有语义能力执行；图快照只携带结果和规则引用，不携带交给浏览器运行的任意规则脚本。

groups 的 members 始终是明确的节点 ID 快照。人工圈选并命名是一项解释；自动识别须保留规则与依据。后续新增节点不会自动进入原结构，重新识别或人工调整须明确提交新的成员快照。结构可以嵌套；部分交叠的结构可以各自描述，但按图工作台契约不能同时折叠。

节点、边和结构使用稳定 ID，说明与坐标变化不换 ID。多个模型调用、代码版本或尝试可以按定义显示为不同节点，也可以在节点数据中汇总；汇总须保留原引用，不把不同尝试合成一条虚假的成功记录。

10.3 完整快照与来源

第一版采用完整快照：外层是 Loom 展示信封，snapshot 原样采用图工作台的 format: "graph", version: 1, graph, view, layout 格式。类型见第 11 章；接收层先校验信封和来源，再将内层交给 graph 的公开文档与图校验入口。不能将整个 Loom 信封误当作图工作台输入。

信封字段固定语义
format / version"loom.graph" / 1。只接受当前明确支持的版本，未知版本保留原内容并拒绝载入。
source.work_id / producer_ref / view_id所属 Work、产出者的固定运行记录引用和非空展示标识。三者确定一条图快照序列；产出者可以提供多个展示。实际来源由 Runtime 的发布记录绑定，正文自报身份不能授权或冒充其他产出者。
source.definition_ref不可变的映射与结构定义引用，包含其选择范围、版本和使用的规则引用。读取该引用不能获取额外权限；规则版本切换须明确采用，不自动把旧图解释为新规则的结果。
source.revision正安全整数，由同一 Work／产出者／展示的持久状态递增并绑定快照内容。相同 revision 的不同内容是冲突；未发布编号可以有空缺，不要求补齐所有中间图。
source.records{after?, through, coverage}：after 排他，through 包含，游标沿用来源及存储世代。complete 只表示定义选择且获准读取的这一范围已完整取得；partial 表示存在缺口。不能按游标字符串比较新旧，也不能把完整读取当作真实世界事实齐全。
snapshot通用图工作台 v1 快照；图中的节点、边、结构、描述及其他调用方数据遵守其公开契约。view.collapsed 只是显示状态。

节点、边与结构的 data 保存原 record_refs、content_refs 及解释。record_refs 使用所属来源可核对的稳定记录 ID；content_refs 与规则引用使用第 11 章的 Ref，basis_refs 可包含这两种依据。Loom 的 data.claim 约定为 {kind, statement, basis_refs, rule_ref?}：observed 必须有足以支持 statement 的原记录或固定内容；derived 必须同时有依据和确定的规则引用；unknown 保留已有依据及缺少项，不能靠空白标签表达。组件只保留和显示这些普通数据，语义校验由产出者负责。人工描述应注明解释或假设；尚未核实的声明使用 unknown，不伪装为观测。

完整快照不要求完整呈现所有记录；选择和省略由 definition_ref 说明。接收层显示产出者、定义版本、已覆盖范围及是否有缺口；具体未知项在图内以普通说明呈现。若图是人工样本，须明确注明样本来源，不能声明为真实运行观测。

10.4 保存、发布与更新

  1. Harness 通过现有 history／content 入口读取获准的固定范围，按确定的定义映射并校验图。恢复时复用原读取结果；重新读取当前记录属于新观察。
  2. 用现有 content.save 保存完整信封；先固定必要字节及保留责任，再确认快照引用。图依赖的原材料按既有内容生命周期保护。
  3. 通过现有 events.publish 发布 loom.graph.snapshot.v1，data.body_ref 指向信封内容；稳定 request_key 绑定原展示与 revision。正文不另塞一份图数据，回执丢失时取得原发布回执。
  4. 获准接收方按发布来源核对信封，读取并校验完整内容，再更新展示。较旧 revision 不覆盖当前图，同 revision 同内容可忽略，冲突明确拒绝。工作台的具体挂载与更新见展示接合。

需要持久接收更新的 Work 使用第 3 章的订阅与输入交付；普通展示页面通过已有获准查询读取发布记录和内容，不因打开图而自动创建 Work。接合不新增图消息总线、图状态存储或一套 RPC。断线、通知遗漏或已清理中间快照时，接收方从获准的既有发布记录取得该展示的新完整快照即可；不要求补放所有增量。事件历史缺口仍按 history_gap 报告，缺少依据或权限撤销时保留上次图并明确显示其覆盖位置与不可继续原因，不假装它是当前事实。

图读取与原 Content／Event 的可见范围一致。引用不是权限凭据；图的标签、描述和数据若复制了受限内容，也必须处于相应授权范围。不得用图通知向无权读原材料的接收者披露秘密。拒绝或缺失须保留具体原因，不能以隐藏节点或空图伪装“没有该事实”。

人工描述、布局、折叠或编辑仅修改图解释与视图。工作台原生导出的 JSON 是 graph 快照，不携带 Loom 的来源确认；再次发布为 Loom 展示时，获准产出者须校验并保存新的 revision，注明人工解释及原覆盖范围，不能冒用原发布回执。编辑不回写原记录、不触发执行，也不自动获得业务验证；运行事实需要从实际记录重新生成。更新规则或自动快照时，接收方明确保留、舍弃或重新应用人工视图，不能无声覆盖尚未保存的编辑。

离线检查复用现有 CLI：将 snapshot 交给 node graph-cli.mjs validate snapshot.json 或 node graph-cli.mjs render snapshot.json --output graph.html。独立 HTML 无需后台或网络，但不是 Runtime 实时视图；交付时同时保留来源信封与覆盖说明。采集和递送由调用方负责，组件不会因打开页面而自动连接 Loom。

10.6 模型输入的信息关系

需要解释模型可见输入怎样追加、取用、摘要或改写时，所属 Harness 定义输入范围、来源关系、转换规则与候选结构，再生成同一种 graph 文档。关系的有效性由产出者按该定义校验；graph 提供结构查询、投影、布局、布线与展示，保留原节点、端点和调用方数据。

Runtime 的调用、工具、文件、等待和授权关系也按各自 Harness 定义表达；通用图不预设一套上下文关系枚举。前缀相符不独立证明直接来源，样本验证不证明真实模型请求被观测；可达路径也不证明任务前置条件已经满足。

Loom 接合时须提供实际模型请求采用的固定输入与来源记录，按本章的 observed／derived／unknown 约定保留依据和未核实提示。显示中的描述、折叠和编辑不会回写原输入或验证信息关系；业务规则或源数据改变后，由 Harness 重新校验、生成和发布。映射后的显示行、候选名称不能自行确立新的业务概念。

10.7 校验与失败处理

输入或操作要求
未知信封／快照版本，重复 ID，缺少端点或结构成员拒绝载入并给出定位；保留原图与未保存编辑，不能部分替换。
旧 revision、相同 revision 不同内容、来源不符旧图不覆盖新图；内容冲突或冒充来源明确拒绝。切换产出者、展示或定义时重新确认比较域。
未覆盖记录、原文缺失或权限变化展示缺口、未知和原覆盖位置，或拒绝读取；不能推断“没有调用”“已经结束”。
折叠、展开、布局和结构调整保持原 ID、原边及实际端点；人工 members 是快照，新节点不会自动纳入。无效交叠折叠拒绝，不能靠修改原连接修复外观。
缺少推导规则或依据，人工样本冒充观测语义层拒绝相应事实声明或明确降为未知／假设；通用图校验通过不表示业务语义成立。
交互编辑或离线导出不产生 Runtime 操作、不修改原事实；保存来源与覆盖范围，关闭前导出尚未保存内容。

组合验收须同时核对原记录、信封、图工作台导出的快照与显示投影，覆盖 A→B→C、原图折叠往返、断线后完整替换、旧版本拒绝和未知事实。图能打开、通用校验通过或布局整齐都不能单独证明映射正确；系统判据见运行与契约验收。
