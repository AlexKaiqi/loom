8.1 Basic：普通任务与主动 Archive

组成是固定指令、交互投影、Bash、精确编辑及模型主动 archive。它不需要 Surface。工具以独立命令为默认，cwd／env 显式，必要状态保存为文件；持久 PTY 是可选会话能力，不视为 Durable。

模型／工具结果 驱动动作
正常完整响应含 tool call 验证并执行工具，闭合每个结果，再调用模型。
正常完整响应无 tool call 交付回答，结束本轮；Work 继续开放。
文本与 tool call 同时存在 仍按工具路径继续，不以已有文本提前结束。
截断、取消、错误、未知结果 保存实际状态；按错误策略修复、重试或等待，不作为正常完成。
明确 yield 保存当前进度与等待，结束活跃推进。 
// runBasicTurn 的内部模型／工具调用都使用受管原语。
while (true) {
  const next = await work.inputs.next({});
  if (next.kind === "closed") return;
  const replyRef = await runBasicTurn(work, next.delivery.input);
  await work.inputs.complete(next.delivery, {
    outcome: "handled", result_ref: replyRef
  });
}

Archive 工具： archive({through, summary})。模型从反馈给出的安全边界选择 through，自行保留要求、更正、进度、未决事项与原文入口；公共代码验证并确认采用。

契约点 规则
状态 {revision, after?, summary_ref?}，由 Harness 的持久状态保存；不新增 history／archive 目录。
保护 当前必需输入、当前 archive 调用、未闭合工具关系和不可拆原生块不能被移走。已闭合的早期工具组可在长任务中归档。
生效 先保存说明和候选，验证消息闭包与容量，再一致提交选择与工具结果。下一次请求使用新 revision。
查回 历史与原文保留，通过 history／只读事实视图读取；不是重跑旧工具。
失败 返回具体范围和原因；不说“已归档”，不偷偷改用自动摘要。

Runtime 在窗口尚有整理余量时提供输入估计、输出预留、来源占用和合法边界。模型忽略提示或必需输入过大时，保存修复状态并停止发送超限请求。摘要质量必须用真实长任务检验，机制本身不保证摘要无遗漏。

8.2 Worksurface：文件化理解与协作

Worksurface 复用 Basic 的普通循环、工具与 Durable 接入，以 Surface 替换上下文选择实现，不同时维护另一份 Basic 的 after／summary。多 Work 协作是可选能力，协作者也可以使用其他 Harness。

## 历史选择
```facts
after = "F0120"
include = ["F0118"]
body_refs = ["F0134"]
```

主模板只解释 include／facts fence；不执行 Shell、SQL、循环或递归模板。include 固定授权资源、文件版本和可选行范围；facts 只有一块，支持 after、include、body_refs。未知字段和非法范围返回定位错误。

模型用普通局部编辑表达选择。编辑成功、投影有效、模型实际采用分别记录；失败候选不偷偷回滚。旧投影仍合法且能容纳诊断时可进入明确修复过程，否则阻塞。文件及每次真实请求保留来源版本。

协作采用第 3 章同一事件契约：发布候选 → 验证方订阅取得输入 → 返回绑定候选版本的报告 → 发起方决定是否采用。创建 Work、定向交付与取消是获准操作；父子关系不自动授予权限、预算或级联终止。

8.3 普通代码：评审管线与修改 Agent

固定文档、rubric、schema 和段落身份；同 Work 中有界并发评审；按项目身份汇合后进入修改 Agent，再评审新版本。每项调用有独立上下文和逐调用记录，不创建一批无必要的子 Work。

固定文档 v7 和评审清单
  → 并发检查各章节／段落／句子（独立 ModelRequest）
  → allSettled 汇合：失败／拒绝／格式错误不算“没有问题”
  → 完整报告 + 原文版本 → 修改 Agent
  → 保存 v8 → 新评审轮次；达到上限则明确停止

100 项完成 37 项后退出：保留 37 项结果，核对原清单中其余操作，再继续。修改 Agent 的每次模型／工具仍单独托管，不能把整个修改循环藏进一个粗粒度 Activity。

监控程序则只需订阅、取得输入、规则判断、按需调用模型或工具和处置输入；不是所有输入都必须启动 LLM。
