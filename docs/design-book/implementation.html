实现与拼接总览

前半部定义 Loom 要交付的目标：作者提交什么、能调用什么、什么结果可信，以及中断后仍须履行哪些责任。本部分面向 Runtime 实现者与部署者，说明怎样用已有事件服务、持久执行引擎、代码运行设施和适配器兑现这些目标。公开接口的字段和成功／失败含义仍由工作契约维护；这里维护组件之间的接合。

按实现问题进入

要解决的问题实现责任与接合入口
事件怎样成为可靠的工作输入？保存发布和来源位置，恢复订阅，向目标 Work 交付；以目标持久受理回执确认移交，再确认消息传输。事件与输入的实现
没有进程在线时，怎样等待、恢复和继续？选定引擎保存控制状态、受管步骤结果、等待、Timer 和执行所有权；把输入准入、推进决定和后续责任接入同一控制组合。持久执行的实现
一份 Harness 的代码如何被执行和管理？核验作者描述，固定代码和实际绑定，安排有限资源，装载隔离环境并提供 SDK；挂起时释放、唤醒后重建，取消和退出时继续处理原责任。Harness 执行管理
模型、用户命令和文件操作怎样取得真实结果？模型 Operation 接到模型能力，命令 Operation 接到 Sandbox 的完整任务入口；按原公开绑定核对结果与停止，接管必要内容后交回控制组合。模型与外部操作、Sandbox 调用与工作接合
组件如何固定成一套可用组合？把公开逻辑资源解析到宿主服务、Profile、SDK、引擎和适配版本；检查兼容性、权限、资源与完整故障轨迹后启用。组件拼接与宿主配置
运行记录怎样展示成图？按 Harness 定义取得获准记录并生成完整快照，将来源信封接到既有 Content／Event，再把通用快照交给图工作台。展示接合

“Harness 如何描述”属于作者目标接口，见第 8 章；“一份描述如何被检查、装载和运行”属于这里的执行管理。描述中的需求不授权执行，也不预先指定实际 Worker 或服务端点。

拼接时的状态归属

需要保留的事实负责保存与确认其他组件怎样使用
发布事件、来源位置与传输积压事件服务和固定内容。事件桥按原身份交付；收到消息不等于目标已经接管输入。
目标输入、处理权、订阅关闭、继续位置与等待Work 选定的一套持久控制组合。桥、SDK 和 runner 请求同一控制提交；临时进程、consumer 与私有会话文件不能另决定如何推进。
本次调用的代码、依赖、SDK、环境和权限范围首次受理固定的调用记录及其受保护材料。执行管理据原绑定装载；配置修改只用于相容的新调用，不能用当前文件覆盖原运行。
外部模型／命令结果、实际停止、费用与未结责任原 Operation 记录和原目的地证据；必要原文通过内容契约保护。持久引擎保存被采用的结果引用；任务重试、进程退出或取消回执不能替代实际效果核对。
图、统计和本地查询索引按覆盖范围生成的派生视图。读取和解释原记录，不取得另一份控制权。

上述是 Loom 的控制与消费责任，不要求每项另建服务或独立进程。Sandbox 独立维护实际执行与资源状态，通过公开回执同 Loom 接合。跨组件的关键交接必须留下可核对的回执；具体准入与恢复规则分别引用共同契约和对应实现篇。

一次动态调用的拼接路径

  1. 作者已保存代码描述和固定业务输入，提交启动请求。执行管理解析并保留实际绑定，Work 控制组合确认原调用责任。
  2. 持久引擎安排可运行调用；执行管理取得当前执行所有权，按原代码和依赖装载环境，并连接限域 SDK。
  3. 受管顺序入口通过 SDK 提出模型、工具或子 Harness 操作，以原生受管步骤确定稳定身份；显式状态入口返回操作意图，由控制组合确认新状态和稳定身份后安排操作。Runtime 保存有效请求和原 Operation，再由对应适配器派发。
  4. 适配器取得并保存实际结果；控制组合记录所采用结果。等待时保留继续依据，执行管理释放闲置专属进程；唤醒后按原版本重建。
  5. 新事件经桥移交到目标持久输入，或原操作／Timer 满足已保存等待；控制组合安排继续，不能在入队和登记等待之间留下漏唤醒窗口。
  6. Harness 交付业务结果。控制组合与执行管理完成或确认接管原操作、子调用和清理责任，再结束调用；临时资源释放不代替责任确认。

发布回执丢失由事件实现核对原发布；输入已受理而 ACK 丢失由桥重投、目标返回原输入回执；runner 退出由持久组合保留继续位置、执行管理重建；外部效果未知由原 Operation 向原目的地核对。组合验证覆盖这些交接，不能以单个组件的绿色测试替代。判据见契约验收。

模型与外部操作

单次模型供应商适配复用 pi-ai；工具操作按Sandbox 调用与工作接合调用公开 TaskExecutor 或会话入口。环境准备、就绪、命令、稳定产物与物理回收由 Sandbox 完整承担，Loom 不再组织具体设施步骤或导入供应商 SDK。可信侧在派发前核对原 Operation 的请求、目的地、执行许可与预算，固定采用的默认值和模型能力。恢复先查原回执；已可能派发而不能确认结果时保留未知，不能因为引擎重试而重新执行一次。

模型请求与原始响应、选定尝试和用量经 Content 保存；Sandbox 返回命令结果与稳定产物，Loom 耐久接管并确认原交付集合，Sandbox 再按原保留条件回收。结果与清理剩余责任分别交回持久控制组合。流式片段和供应商取消分别按模型结果契约处理。模型适配器只完成一次请求，完整 Agent loop 仍属于 Harness，决定是否再次推理或执行返回工具。

SDK 与可信侧的通信

受管 SDK 暴露第 11 章的目标接口。同进程可以调用同一受信端口；跨进程的参考接法采用 JSON-RPC 2.0，并固定通信认证、数据转换和适配版本。JSON-RPC 的 id 只关联一次请求和响应；稳定 request_key 与受管步骤身份用于跨连接核对业务操作。通信载荷使用明确 JSON 类型和 Content 引用，不直接序列化 Node 类实例或供应商私有异常。

身份、Work／run 范围及执行所有权从受信连接取得，管理凭据留在可信侧。传输重试复用原操作身份；通信成功不独立确认持久受理或外部效果。隔离进程中的普通 RPC Promise 也不自动保存继续位置，必须接到原生持久执行机制。

从已有组件取得零件

事件与输入实现选用 NATS／JetStream；动态顺序代码优先验证 Resonate 组合 R，Temporal 组合 T 提供预装 Workflow 与动态显式状态接法，DSH／Cordis 与可嵌入内核的组合 E 保留候选范围。各选件如何兑现同一目标，由相应实现篇说明，不能反过来缩减作者接口。

Pi／DSH 的上下文转换、工具 schema、响应分类与推进策略可以成为 Harness 库；完整 loop 要把每次模型、工具、输入和等待接到受管入口。Cordis 可选地管理进程内依赖、scope 和装卸；卸载先完成或确认交接在途责任。Loom 维护必要的不可变代码装载、受信范围、原操作核对和内容保留接合，不复制模型循环或持久执行 journal。选件依据与未验证范围见选型与证据。

展示接合

目标接合由 Harness 或已有语义适配器按图来源信封契约生成快照，用现有 Content／Event 保存和发布。获准展示接收层校验来源、版本与完整快照后，调用 graph 的 index.mjs 公开 validateGraph(snapshot.graph)；浏览器入口以 await prepare(snapshot) 得到 {projection, geometry}，再以 mountGraph(element, projection.graph, geometry) 挂载。收到新快照后重新 prepare，再用 handle.update(projection.graph, geometry) 更新。接收层负责乱序、权限和未保存人工编辑的处理；graph 负责通用图展示，不另建图存储、消息总线或 Harness 专用前端。此处规定目标接合，不表示 Loom Runtime 已经实现图发布和接收。

模型输入的实际采用与来源采集属于 Loom 的接合；直接信息关系、候选结构和业务状态的校验留在所属 Harness。图上的选择和操作意图由调用方处理，通用查询、折叠或连线不决定业务执行。组件入口、坐标、端口及投影映射依graph 公开契约维护。
