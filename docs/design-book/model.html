05. 模型访问

5.1 Harness 要什么

提交一个独立模型请求，得到它的响应、结束原因、用量与原文；同一工作可以批量调用，也可以把响应交给自己的工具循环。

调用不要求 Agent 对象、Surface 或全局 messages。模型适配复用 pi-ai；模型选择、Prompt、结构化判断和是否继续由消费者定义。

5.2 调用契约

方法 成功含义
model.describe(selection) 返回当前可用模型、窗口、支持的媒体／输出/schema 能力及依据。发现不等于授权。
model.submit(request) 返回原操作 id、有效请求引用和绑定；请求与执行责任已受理。
model.result(operation_id) 取得同一操作已选定的完整结果；未就绪时持久等待。
model.inspect(operation_id) 返回 pending／running／unknown／complete、取消观测与结果引用。
model.cancel(...) 记录取消请求，不证明供应商未计算或未计费。
model.invoke(request) submit + result；不执行返回的 tool call，不内置重试循环。

请求必须表达本次模型、messages | messages_ref | projection_ref 三选一、输出要求、输出上限和预算范围。工具定义、缓存偏好和 stage／item／pass 归因可选；缺省值在受理时固定。完整类型见附录 A.1。

const response = await work.model.invoke({
  schema_version: 1,
  request_key: "review:document-v7:section-3",
  model: { service: "reviewer" },
  input: { messages: [
    { role: "system", content: rubricText },
    { role: "user", content: sectionText }
  ] },
  output: { mode: "json_schema", schema_ref: findingSchemaRef,
    enforcement: "provider_required" },
  limits: { max_output_tokens: 1500, budget_ref: "review-budget" },
  cache: { mode: "prefer_prefix" },
  attribution: { stage: "review", item: "section-3", pass: 0 }
});

5.3 结果、流与缓存

结果区分正常停止、工具请求、长度截断、错误与取消；同时保存实际请求／响应引用、选定 attempt、tool calls、schema 校验状态及 usage。JSON 合法不证明判断正确，空工具数组不证明调用成功。 不支持必需 schema 能力时拒绝；不得静默降级为文本。

流式片段绑定 operation／attempt／序号，属于可观察进度。部分输出不当作完整结果，重连不伪装成从原 token 续生成；采用片段作控制决定的运行方式必须记录该决定的依据。

前缀缓存是优化，不是持久保证或结果去重。固定 rubric、序列化和工具/schema 顺序有助于前缀稳定；命中按实际 usage 记录，不承诺每次命中、不减少上下文占用。完整输入与输出仍按内容契约保存。

5.4 预算与并发准入

阶段 规则
范围 受信配置授予 budget_ref、单位、上限、上级和版本；stage 标签不能自授额度。
准入 新 attempt 在派发前按保守上界保留额度；并发请求共同仲裁，不能分别花同一余额。
结算 每个真实 attempt 保存 usage 与价格依据；重放旧结果不再扣费，新尝试仍计费。
未知 已可能派发但用量不明时保留占用或按声明方式保守结算，不能填零或取消即退还。
不足 明确拒绝或按已声明规则排队；不丢输入、不无限重试。

硬费用上限依赖可信单次消耗上界；只具备估计时必须标为软预算或拒绝 hard-limit 要求。默认不按预计缓存命中缩减保留额。并发槽、费用预算、上下文窗口是三种不同限制。
