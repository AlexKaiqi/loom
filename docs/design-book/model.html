05. 模型访问

5.1 一次调用在持续工作中的位置

Harness 用模型完成某一步判断，例如提出疑点、评审证据或选择工具。Runtime 接收这次请求，调用选定模型，并保存响应、结束原因、用量和原文。如何检查回答、执行工具，以及是否再次调用模型，由 Harness 决定。

模型接口接受独立请求，因此同一 Work 可以顺序或并发调用不同上下文。供应商协议适配复用 pi-ai；接入不要求使用特定 Agent 对象、Surface 或全局聊天记录。

5.2 调用契约

方法 成功含义
model.describe(selection) 返回当前可用模型、窗口、支持的媒体／输出/schema 能力及依据。发现不等于授权。
model.submit(request) 返回原操作 id、有效请求引用和绑定；请求与执行责任已受理。
model.result(operation_id) 取得同一操作已选定的完整结果；未就绪时持久等待。
model.inspect(operation_id) 返回 pending／running／unknown／complete、取消观测与结果引用。
model.cancel(...) 记录取消请求，不证明供应商未计算或未计费。
model.invoke(request) submit + result；不执行返回的 tool call，不内置重试循环。

请求必须表达本次模型、messages | messages_ref | projection_ref 三选一、输出要求、输出上限和预算范围。工具定义和缓存偏好可选；stage / item / pass 可标明所属阶段、评审项和轮次。缺省值在受理时固定。完整类型见附录 A.1。

const response = await work.model.invoke({
  schema_version: 1,
  request_key: "review:document-v7:section-3",
  model: { service: "reviewer" },
  input: { messages: [
    { role: "system", content: rubricText },
    { role: "user", content: sectionText }
  ] },
  output: { mode: "json_schema", schema_ref: findingSchemaRef,
    enforcement: "provider_required" },
  limits: { max_output_tokens: 1500, budget_ref: "review-budget" },
  cache: { mode: "prefer_prefix" },
  attribution: { stage: "review", item: "section-3", pass: 0 }
});

5.3 结果、流与缓存

结果须区分正常停止、工具请求、长度截断、错误与取消，并保留实际请求和响应、选定尝试、工具调用、格式校验结果及用量。JSON 合法不证明判断正确，空工具数组不证明调用成功。 不支持必需 schema 能力时拒绝；不得静默降级为文本。

流式片段绑定 operation／attempt／序号，属于可观察进度。部分输出不当作完整结果，重连不伪装成从原 token 续生成；如果 Harness 根据片段提前作出决定，必须保存当时采用的片段和决定。

前缀缓存是优化，不是持久保证或结果去重。固定评审标准、序列化格式以及工具和 schema 的顺序，有助于保持请求前缀稳定。缓存是否命中按实际用量记录；命中仍然占用上下文窗口。完整输入与输出仍按内容契约保存。

5.4 预算与并发准入

阶段 规则
范围 受信配置授予 budget_ref、单位、上限、上级和版本；stage 标签不能自授额度。
准入 每次实际尝试在派发前按消耗上界预留额度；并发请求共用同一准入检查，不能重复支配同一余额。
结算 每个真实 attempt 保存 usage 与价格依据；恢复时复用已有结果不产生新的调用费用；新尝试单独计费。
未知 已可能派发但用量不明时保留占用或按声明方式保守结算，不能填零或取消即退还。
不足 明确拒绝或按已声明规则排队；不丢输入、不无限重试。

承诺硬费用上限，必须有可信的单次消耗上界；只有估计值时，应标明软预算，或拒绝硬上限要求。默认不按预计缓存命中缩减保留额。并发槽、费用预算、上下文窗口是三种不同限制。
