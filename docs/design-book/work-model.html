02. 工作模型与共同约定

2.1 必要概念

对象 定义与边界
Work 持续存在的工作身份及其配置、必要状态、记录和未结事项。不是进程、项目目录或单条聊天。
Harness 组织上下文、操作与等待的工作程序。每次运行绑定确定版本和一种可恢复入口。
Event / Input Event 是有来源、有类型的发布记录；Input 是某个 Work 已受理、需要明确处置的信息。
Operation / Effect 一次受托操作，绑定稳定身份、原请求、原目的地、实际尝试和结果。模型调用、命令、发布均可按此托管。
等待 对输入、操作结果或时间的持久依赖。属于工作状态，不依赖活着的回调。
内容 / 上下文 内容是可读取、可版本化的资料；上下文是一次模型请求实际采用的信息。Surface 是可选维护方式。

Userspace 是独立项目、个人资料或数据资源。Work 使用其获准版本或工作副本，不取得项目所有权。Target 是 Work 内的逻辑执行目标，Allocation 是一次实际资源绑定。

2.2 所有写操作共用的规则

契约 确定行为
C1 身份绑定 身份来自受信连接。request_key 在调用来源与目标 Work 的作用域内绑定方法和有效请求；不能复用为另一种操作。SDK 保存解析后的默认值、内容及目的地。
C2 重复请求 同键同请求返回原回执；同键不同请求返回 identity_conflict。回执丢失后核对原键，不另造一次调用。相同正文配新键是新意图。
C3 回执 回执说明该次提交确认了什么，不代替对象当前状态。写入“已受理”不等于已开始、已完成或业务正确。
C4 恢复 已确认结果复用；未完成事项仍有执行或核对责任。超时和连接断开不能被解释成“从未执行”。
C5 授权 请求、历史读取和实际执行都核验所需权限；引用、队列名、目录名和业务标签不授予权限。旧回执的返回也须有读取权。
C6 一致确认 确认依赖的内容、状态与后续责任必须可恢复地关联。不能先报告成功，之后才尽力保存唯一必要内容。
C7 保留 未处理输入、在途操作、等待和已确认继续状态所需的记录受保护。归档上下文、卸载组件与回收环境不删除这些责任。
C8 可见失败 校验拒绝、资源不足、暂时不可用、结果未知分别返回稳定错误种类。没有确认结果的网络失败，仍需按原身份核对。

重复请求先核对原提交；有权读取时返回原回执，不因当前版本或生命周期已经变化而误报为一次新的过期操作。未提交的新操作才继续检查当前 owner 与预期版本。

request_key 不是 RPC 连接的 id，也不是模型生成的 tool-call ID。业务对外重试使用显式键；内部顺序代码可由 Durable 绑定保存稳定调用身份。普通内存计数器或函数名不足以提供重启后的身份。

2.3 Work 不只有一个“运行状态”

状态维度 需要区分的状态
生命周期 open → closing → closed。等待不等于关闭。关闭须处置或转交未结事项。
输入 queued → processing → disposed。处理中可以等待或恢复；处置结果为 handled、failed 或 ignored。
操作 尚未派发、已可能派发、原结果已确认；取消请求与实际停止另记。
等待 未满足、已匹配、已取消／超时。得到答复不等于答复为批准。

Work 可以同时有待处理输入、某个未知操作和另一个已完成结果。未知发送阻止冲突重发，不必阻止无关的只读工作。界面可显示摘要，但不得用一个 done／failed 覆盖以上关系。

2.4 并发与顺序

控制状态有可确认的提交顺序，不等于操作必须串行。 同一 Work 可发起多个独立模型请求，每个使用自己的输入、操作身份和预算。共享文件写入按实际资源范围协调。

默认输入按目标 Work 的受理顺序取得；不从时间戳推导跨来源全局顺序。业务必须先 A 后 B 时，Harness 显式表达依赖。多次模型调用或多个 Task 不自动变成多个 Work。
