06. 用户环境：Sandbox 调用

6.1 Work 工具与 Sandbox

Harness 通过用户环境执行项目代码、构建、测试或处理文件。受控命令、文件准备、实际执行域、结果与产物交付，以及资源释放，由独立的 Sandbox 能力完整提供。Loom 将这项能力接到 Work 的工具接口：限定授权和预算，保存原 Operation，接管结果及必要内容，并让等待和未结责任跨中断继续。

普通工具一次提交命令、获准 Target、文件要求和限额。Sandbox 在内部完成环境准备、能力核验、文件就绪、命令执行、稳定产物交付及清理；Harness 和 Runtime 不组装后端的 Acquire → Execute → Stabilize → Export → Release。作者不选择供应商 SDK、不填写后端管理参数，也不根据容器或进程状态猜测业务完成。

本章规定 Loom 如何消费 Sandbox；独立执行的目标与后端定义由 Sandbox 维护，目标材料为该仓库的 docs/user-environment.md 与 docs/backend-reference.md。只有实际绑定的公开版本满足这些要求并通过组合验收，Loom 才能启用该环境。具体交接见Sandbox 调用与工作接合。

Agent 实际拿到什么

在 Basic Harness 中，模型看到的是在获准用户环境执行的 bash 工具：给出命令，读取输出，再决定下一条命令。Harness 把工具接到 Runtime 的 execution.submit/result；Runtime 消费 Sandbox 的完整任务或已绑定公开会话执行能力。其它 Harness 可以提供 Exec、文件或专用工具，不必向模型展示同一组工具。

模型 tool call → Harness 工具适配 → Runtime 保存原 Operation 并核验授权 → Sandbox 执行 → Runtime 接管结果 → Harness 把工具结果交回模型。

例如模型提交下面的业务参数。Target 可由 Harness 预先固定；只有需要在多个获准目标间选择时才展示给模型。请求键、服务绑定、文件基线、原生身份和管理凭据由受信侧处理。

{
  "name": "bash",
  "arguments": {
    "command": "pytest -q",
    "cwd": {
      "alias": "app",
      "path": "."
    },
    "timeout_ms": "120000"
  }
}

Sandbox 的任务结果由 Runtime 保存，再由 Harness 整理成模型可读的工具结果。下例是 Basic 的结果摘要，不另定义 Sandbox 协议；完整输出、产物和原始观测仍可按受保护引用取得。

{
  "status": "complete",
  "exit_code": 0,
  "stdout": "3 passed",
  "stderr": ""
}

运行中、输出截断、执行未知或内容尚未接管时，工具结果明确表达这些状态；不能先给模型成功结果再补保存。等待过长时，Harness 可以保留原 Operation 后让模型查询或等待它，停止请求仍指向原命令，不靠再次提交来取得结果。Bash 可以完成读文件、修改和测试；专用文件工具是 Harness 的选择。

执行 Harness 程序仍需要代码装载、受管 SDK、调用身份和恢复绑定，由Harness 执行管理负责。它可以复用 Sandbox 的运行与隔离设施；一次普通命令提交不会自动成为可恢复的 Harness 调用。

6.2 提交、结果与原请求

Loom 作者入口输入确认与边界
execution.submit稳定键、逻辑 Target、命令、获准文件要求和限额；可选原会话引用。Loom 已保存有效请求、固定目的地及执行责任，返回原 Operation。环境准备和执行结果分别观测，不把受理当作命令成功。
execution.result原 Operation id。等待同一请求的已保存结果、产物接管状态及剩余责任；不创建第二次执行。
execution.inspect原 Operation id。读取已保存观测，必要时通过 Sandbox 的原请求入口核对。命令、通信、内容和资源状态分别表达。
execution.cancel取消键与原 Operation id。保存停止原请求的责任，按原 Sandbox 身份请求取消。回执不证明停止、费用结清或资源已删除。

Bash 工具表达 command；通用 Exec 表达 argv，不隐式经过 Shell。Loom 固定这些业务参数和授权资源别名，按 Sandbox 的已绑定公开格式交付；具体 Shell、执行路径与后端映射由 Sandbox 确认。完整业务载荷见tool.exec/1。

返回结果要区分已知命令结果与未知/失败的通信和执行观测。非零退出仍可是一份已知结果，业务是否成功由 Harness 判断。输出缺口、取消、超时、文件未接管和清理失败不能合成一个成功退出码。恢复同一次 result 复用原结果或核对原对象，不用重跑命令取得日志。

6.3 Target 与可选会话

Harness 从 Work 已获准的逻辑 Target 中选择满足系统、工具、网络、资源、文件和原请求核对要求的环境。宿主将 Target 连接到一个固定版本的 Sandbox 服务或执行方式；Sandbox 负责实际设施与能力检查。必要能力不满足、服务未就绪或绑定版本不相容时明确拒绝，不能自动转到不受限 Shell或另一后端重做原请求。

普通命令使用完整任务能力；一次提交不要求创建一份新物理环境。连续工具调用固定同一获准工作副本或其已接管内容版本，下一条命令看到前一条已确认的文件修改。shared 可以继续访问原副本，transfer 可以把新版本准备到下一次执行环境；环境重建不能把已确认文件退回初始版本。需要并发修改时另按基线及写入范围协调，不能把未稳定文件当作下一条命令的输入。

需要持续的状态使用方式与保证
工作文件以 Userspace 工作副本和 Content 版本持续；与 Shell 是否常驻、物理环境是否重建分别确认。
同一执行环境通过 Sandbox 已声明的公开会话能力固定原环境。需要保留已安装工具、后台服务或端口时，明确环境保留要求；会话复用不自动保留某个 Shell 的状态。
同一个 Shell／交互终端只有明确启用持久 Shell 或 PTY 的公开能力时，才保留进程内的 cwd、变量或交互状态。终端输入、输出读取、信号、重连及生命周期保证由 Sandbox 定义，Loom 保存原对象关联；不从“支持会话”推定“支持终端”。

基础 tool.exec/1 每次启动独立的非交互命令，cwd 和 env 每次固定；上一条 cd 或 export 不成为下一条的隐含参数。同一环境里连续执行命令也遵守这一规则。公开会话的创建、执行、重连、续期和结束随 Sandbox 的版本维护；会话引用不授予新 Work、目录、命令或管理权限。持久 Shell／PTY 的进程退出仍可能丢失交互状态，不能冒充工作内容及操作的耐久恢复。

原来按 allocation.acquire/inspect/release 分解的环境管理，不是普通工具的必经作者流程。确有会话需求时才采用明确的公开会话入口；Loom 保存其受理与剩余责任，并保持查询和取消针对原会话。不可将后端私有 Provider 或原生资源 id 暴露为作者必须组装的接口。

Sandbox 维护本机进程、独立容器、自部署服务和托管云环境的部署、配置与限制。Loom 只固定获准的逻辑引用、资源范围和消费版本；接口或限制变化按组合验证启用，不按供应商名称推定能力。

6.4 文件接管与项目整合

请求明确可读/可写资源、确定基线和必须返回的产物范围。Loom 从 Work 授权取得这些要求；Sandbox 提供实际执行路径、准备文件，并通过稳定来源与完整传输交付必要字节。共享与传输是能力内部落实文件要求的方式，作者不靠临时路径或上传成功推断内容已保存。

交接负责方与确认
可执行文件Sandbox 核验文件就绪及实际访问范围，给出与原任务/会话绑定的路径映射；Loom 只向作者暴露获准根。
命令结果与稳定产物Sandbox 给出实际结果范围、输出完整性、稳定来源/产物和必要保留条件；缺少稳定证明时保持未知或未就绪，不要求 Loom 拼冻结与导出步骤。
Work 内容接管Loom 校验字节及摘要，完成耐久保存和引用保护后确认接管。Sandbox 才可解除相应保留或清理唯一来源；交接失败保持原责任。
共享项目整合Loom 按新内容和预期基线条件更新，冲突显式返回。执行副本已保存不等于用户项目已更新。

不同 Work 默认使用独立可写副本，只读材料可以共享。Sandbox 负责物理范围与稳定写入边界，Loom 负责 Userspace 的授权、内容版本及整合。暂停、进程退出和相同摘要都不能单独证明内容稳定；相应保证必须来自 Sandbox 已验证的公开交付契约。

6.5 未知、取消与清理

任务环境不能取得管理凭据、Loom 控制通道或其他 Work 私有状态。Loom 决定本次 Work 的可用能力与额度；Sandbox 实际落实文件、网络、执行域和资源限制。超时、输出上限或取消后的停止范围随 Sandbox 公开契约确认；后端无法满足必需约束时不执行。

通信中断不证明未执行，PID、容器 stopped、CLI 退出或客户端 close 都不独立证明原任务及相关写入者已停止。Sandbox 持有原生身份、执行和清理状态，提供原对象查询与停止证据；Loom 保存这些观测及未结 Operation，未知时阻止冲突写入，不换目的地重放。

Work closing 停止新增业务意图，已有结果接收、原对象核对、内容接管和清理仍须完成或确认持久交接。清理失败单独报告，不能覆盖已知业务结果，不删除独立 Userspace。Sandbox 的执行检查点不决定 Work 下一步，Loom 的 Operation 终态也不伪造 Sandbox 已停止或已删除的事实。

模型在获准环境编辑或构建 Harness 候选时，只能修改获准材料；不能写 Runtime 私有记录或当前调用的固定代码。范围内 loom CLI 是单独授权的消费入口，不注入普通用户项目命令环境。
