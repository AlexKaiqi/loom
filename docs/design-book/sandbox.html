06. Sandbox 与任务内容

6.1 从行动请求到受控执行

Harness 提出要执行的命令或文件操作，以及所需的环境能力。Runtime 根据 Target 配置准备环境和获准的工作副本，检查权限、网络及资源限制，再交给 Provider 执行。返回结果须能追溯到原操作；断线后的查询与取消也必须针对同一次执行。

Harness 作者通过工具或执行接口使用环境，部署者选择具体后端。Provider 的共同接口是 Describe / Acquire / InspectAllocation / Release；命令执行、命令查询、停止、稳定内容和传输按能力分别声明。

6.2 作者接口与结果

入口 必须绑定的输入 回执含义
allocation.acquire Target、能力要求、资源范围、稳定键。 分配身份已建立；资源已创建与能力 Ready 分别报告。
execution.submit 稳定键、原 Allocation、argv、cwd、env、stdin、限额。 命令请求及责任已受理，不等于进程成功退出。
execution.result/inspect 原操作 id。 原执行的结果／状态；输出与 task、wrapper、transport 的观测范围分开。
execution.cancel 原操作 id、取消键。 请求停止原执行；不能暗中停止其他 Work 共用的环境。
allocation.release 原分配身份与释放要求。 结束使用和删除资源分别确认；不删除独立 Userspace。

Bash 工具将 command 明确转换为该环境的 Bash argv；通用 Exec 直接接收 argv，不隐式经过 Shell。cwd 使用授权别名与根内相对路径；env 不继承管理凭据。完整载荷和 Provider 类型见附录 A.4。

6.3 执行后端的适用范围

位置／用途 对接工具 接口 设计范围
设计中的默认原生执行（macOS／Linux） Anthropic SRT 官方库 initialize / wrapWithSandbox / reset，受信进程启动。 普通文件、代码、构建与测试；按锁定平台验证。
macOS 本机独立任务环境 Apple container 官方 CLI。 按任务的环境和隔离要求显式选择。
Linux 本机独立任务环境 rootless Podman 官方 CLI。 不要求任务模型开发镜像，环境由部署配置。
自部署服务器／集群 OpenSandbox 官方 Go SDK／Lifecycle、Execd API。 生命周期与命令端点分别认证。
Cloudflare 账户中的云端环境 Sandbox SDK + 官方 Sandbox Bridge 部署的 HTTPS Bridge。 不是无需部署的公共共享端点。
SaaS 环境 E2B 官方 JavaScript SDK。 只使用沙箱，不接入其 Agent 循环。
研究项 OpenAI Containers／Hosted Shell 已研究资料中的容器、文件与模型驱动 Shell。 独立通用 Exec 尚未在所列资料确认，不注册完整 Provider。

各后端的接口、能力限制与调用时序见附录 A.5。表中列出的是设计接入范围；可用性须按发布版本的安装、安全与恢复证据判断。

6.4 文件与资源

Runtime 将 Target 解析为宿主 Profile、Provider 和服务，并在首次受理时保存实际 Allocation 绑定。查询、停止和归还不按当前 Profile 重新路由；失败也不换 Provider 重跑。

文件方式 执行前后做什么 必须保留的边界
shared 直接使用或挂载获准的持久工作副本，无需额外传输。 文件可见不等于稳定版本，仍需稳定读取和耐久确认。
transfer 导入确定基线，执行后从稳定来源导出必要变更。 未交付内容仍是责任，不能先释放临时环境。
共享项目整合 使用新内容和预期目标基线条件更新。 保存自己的工作副本不自动合入项目；冲突显式返回。

不同 Work 或 Target 默认使用独立可写副本；只读材料可以共享。保存内容前须取得稳定来源，例如确认所有相关写入者已暂停或停止、取得不可变候选，或使用经验证的快照。两次扫描摘要相同不足以证明期间没有并发写入；暂停也不能当作永久停止。

6.5 权限、失联与回收

Runtime 按宿主授权限制任务代码可读写的文件、可访问的服务和网络、可使用的预算与资源。任务环境不得取得管理凭据、控制通道或其他 Work 的私有状态。每个后端须验证这些限制；能力不足时拒绝执行，不能自动回退到不受限 Shell。

默认原生执行的设计目标是不要求 Loom 持有宿主 root；各后端的安装前提须分别声明。环境隔离控制操作的影响范围，业务正确性仍由 Harness 的检查流程判断。

进程退出码、容器 stopped 状态、PID 或 CLI 退出，不足以单独证明所有相关写入者已经停止。原执行身份不足时保留 unknown，阻止冲突写入；可以继续保存已有结果。保存必要内容和诊断后，把清理交给独立持久任务；清理失败须单独报告，不能覆盖已经取得的业务结果。
