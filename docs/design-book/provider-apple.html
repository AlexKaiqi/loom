Apple container CLI

Apple container 用于在 macOS 上提供独立任务环境。适配器通过官方 CLI 管理环境、挂载和生命周期；发行或部署者提供环境模板。接入前须核对所锁定版本的宿主要求，并验证所需能力。[S18][S24]

Loom 阶段真实 CLI 与约束异常与内容
预检检查固定版本、宿主支持和 container system status --format json；验证需要的辅助服务解析结构化状态，不依赖成功提示文案；安装所需管理员步骤须在部署说明中列明。
Acquire保存 Runtime 生成的不可复用名称与申请；container create 后 container start；授权根映射为 --mount；无网用 --network none固定镜像完整摘要；环境准备阶段不能隐式执行用户脚本。回执丢失 inspect 原对象、labels 和创建证据，不创建第二个。
Executecontainer exec --workdir <实际路径> <原容器> <argv…>，Go os/exec 直接参数调用保留实际 code/输出及来源；CLI 连接退出与客体命令终态按原生保证区分。stdin/流行为按锁定版本测定。
Inspect／Stop资源用 inspect，日志用 logs；停止独占资源可用 stop，按明确范围核验容器 inspect/logs 不是每个 exec 的完整历史；没有独立命令查询/停止就声明缺失，不能超出授权范围停止其他共享工作。
内容获准宿主副本映射到 /workspace；由宿主捕获稳定版本，不调用传输rootfs export 不覆盖 bind mount 的稳定性保证。暂停/停止/快照语义分别验证；禁止以 kill 替代请求的 freeze。
Release内容和必要诊断受保护后，stop/inspect，再独立 delete 原对象不用 --rm、--all 或 stopped+TTL 自动判任务完成；VM 结束不删除宿主副本与项目。
