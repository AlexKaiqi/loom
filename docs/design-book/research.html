B.1 组件选择与候选方案

对象 学习／使用什么 边界与判断
NATS／JetStream 持久发布、离线消费、积压与重投。 目标事件实现；Work 的输入受理与业务处理仍由 Loom 确认。
Temporal 控制流重放、Activity、消息、Timer、任务安排。 参考 T 分清预装 Workflow 与动态显式状态接法；Worker 代码装载不自动覆盖运行时生成的顺序 Harness。
DSH 模型访问与 loop 分离；工具管线；语义事件、投影、检查点。 复用上下文转换、schema、响应分类和推进策略；完整 loop 的模型、工具和等待改接受管原语，私有 Persistence 不成为第二权威。
Cordis 依赖、scope、注册和临时实例装卸。 可用于管理进程内组件的依赖和生命周期；持久状态仍由选定执行内核管理。
Resonate 受管 async、promise／task 协议、可执行规范和轨迹检查。 动态受管顺序代码的优先验证组合 R；固定入口、不可变代码装载与隔离 SDK 接合仍须验证，不宣称组合已完成。
Durable Task／Dapr 可嵌入执行内核、任务完成与后续责任交接。 候选 E；抽取内核不自动继承完整部署的所有保证。
DBOS／LangGraph 库式执行、步骤记录、部分结果与检查点。 比较完整运行方式，既验证状态恢复，也验证没有活跃进程时能否按输入或到期条件唤醒。
pi-ai 单次模型供应商适配。 沿用单次模型适配；Pi agent-core 的上下文转换、工具 schema 与循环策略按需复用，完整 loop 接到 Loom 的受管操作，不强制所有 Harness 采用它。
graph-workbench 节点、边、结构成员快照、描述、布局与可逆折叠；公开 CLI 与图会话。 通用展示组件；图结构的业务含义由 Harness 定义。采集、发布与运行事实关联由 Loom 接入，不另造前端。公开契约。
context-information-graph 模型输入的直接来源关系校验、追加链候选计算和通用快照转换。 上下文信息关系的可选零件；不作为所有 Harness 的概念体系，也不由显示折叠确认概念。公开契约。
Git／不可变 records／SQLite 视图 内容版本、原文字节、固定范围查询。 执行组合须声明各自保存哪些权威记录；查询视图不能独立决定下一步。

已选择的基础零件、候选执行接法和需新增的接合分别表述。动态 Harness 先验证组合 R的原生受管执行；T 的有限推进接法只覆盖显式状态作者形式。其他历史比较项不等于同时维护多套运行路径。采用开源零件时固定版本、公开接口和许可范围，Loom 只维护调用责任、受信范围与接合差异。

DSH 的参考价值在于分开模型访问、推进循环、工具与持久状态。重点考察 ctx.llm、Session／Persistence／Checkpoint、工具管线及状态所有权。架构依据、模型服务、循环、上下文。这些材料用于理解分工，采用时仍须验证 Loom 的工作契约。

B.2 Sandbox 责任与消费依据

OnDemand Sandbox 的能力描述、execution/contracts 及会话契约负责独立环境与受控任务交付；Loom 保存持续工作中的授权、操作身份、结果接管和恢复关联。源码固定在 components/sandbox，选定组合必须匹配该公开契约及实际验证范围。

后端选件、供应商 SDK／CLI、部署要求和版本来源归 Sandbox 的 docs/backend-reference.md、docs/backends/ 与 docs/backend-sources.html。Loom 的消费要求见第 6 章，调用及检查点接合见A.4；不能把原生接口存在或 Sandbox 组件通过升级为工作恢复组合已经成立。

B.4 验证范围与报告要求

文档检查验证内部链接、锚点、代码块语法和页面呈现。修改类型或示例时，还须检查示例与声明是否一致，区分外部显式请求键与受管日志派生键，并验证图示数据经现有组件的公开入口接受。文档检查不能证明引擎、模型服务、权限或故障恢复已满足契约。

实现验证按可执行判据开展。报告须说明源码与依赖版本、配置、时间、实际环境、正常及失败路径，并提供可核对的记录。状态模型检查和测试替身只能证明其覆盖的假设；事件桥接、跨运行实例、退订竞争及真实模型调用需要组合验证。动态 Harness 还须覆盖不可变代码装载、A→B→C、回执丢失、部分并行完成、等待释放、原绑定恢复与未结责任接管；图展示验证来源范围、规则版本、乱序发布和折叠不改变原记录。

测试结果保存在对应版本的验证报告中，本页只维护检查要求。找不到报告或报告与当前版本不符时，状态应记为未验证。
