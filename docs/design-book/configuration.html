A.6 配置、组件组织与版本

Work 配置声明 Harness 版本、模型服务和任务所需资源；宿主配置决定这些声明如何绑定到实际服务、目录及授权。下面使用 Temporal 参考组合 T 的结构 3 格式，其他执行组合须声明自己的配置格式。

schema_version = 3

[harness]
path = "harness"
workflow_type = "basicHarness"
release = "basic-r1"
state_schema = 1

[durable]
service = "primary-durable"

[model]
service = "primary-model"

[userspaces.app]
resource = "project-app"
access = "write"
delivery = "per-tool"

[targets.default]
profile = "local-default"
userspaces = ["app"]

Basic 不要求 [surface]；Worksurface 的 release 要求 surface.path。Work 只声明逻辑资源；宿主配置解析物理目录、服务端点和私有 credential_ref。发布前须验证完整安装流程，包括逻辑引用解析、能力检查和授权绑定。

宿主服务、Provider 配置与绑定示例
# work.toml 结构 3 的默认 Target 配置片段。
[targets.default]
profile = "local-default"
userspaces = ["app", "reference"]
# macOS / Linux 两种安装版共用形状；发行负责解析确定依赖。
[services.local]
provider = "local-process/v1"
endpoint = "local://host-6"

[profiles.local-default]
service = "local"

[profiles.local-default.options]
policy_ref = "policy:default-tool-scope@locked"
toolchain_ref = "toolchain:installed-host@locked"
timeout_seconds = 120
# 仅在额外 Target 被显式绑定时生效。并非所有用户必须配置。
[services.independent-local]
provider = "apple-container/v1"
endpoint = "local://host-6"

[profiles.independent-local]
service = "independent-local"

[profiles.independent-local.options]
cli_ref = "tool:apple-container/1.4.1"
image_ref = "image:approved-task-environment@locked"
network_policy_ref = "policy:no-egress@locked"
cpus = "2"
memory = "2G"
timeout_seconds = 120

[services.remote]
provider = "opensandbox/v1"
endpoint = "https://sandbox.example.invalid/v1"

[profiles.remote]
service = "remote"

[profiles.remote.options]
sdk_ref = "sdk:opensandbox-go@locked"
deployment_ref = "deployment:approved-remote@locked"
request_timeout_seconds = 30
绑定规定
local-process/v1policy_ref、toolchain_ref、正整数 timeout_seconds；toolchain_ref 解析到固定 SRT／Node／OS 组合，options_json 保存实际配置。
apple-container/v1cli_ref、image_ref、network_policy_ref、cpus、memory、timeout_seconds。引用解析为不可变版本，无网配置使用已验证的 --network none。
opensandbox/v1sdk_ref、deployment_ref、request_timeout_seconds。部署对象固定 API／spec、image／platform、挂载或传输、网络、TTL 和保留条件；凭据单独注入。配置由绑定的适配器版本验证。
共同Profile 必须解析为要求快照与完整 provider/service/endpoint/options_json。未知键拒绝，身份/凭据来自宿主；模型不能把 image、path 或参数当成自授权。未解析引用或未通过能力组合不派发。

若后端不能提供请求所需的持续进程、冻结、结果查询或网络限制，须拒绝该能力组合。部署者可以改选满足要求的已验证后端；替换只适用于后续新分配，已有操作仍须向原后端核对。

宿主配置中的 @locked 引用必须解析为确定部署、依赖摘要和私有凭据引用；未解析时保持 not_ready。Linux Podman 与 macOS Apple 可由各自发行绑定同一逻辑 Profile；取得 Allocation 后使用固定服务，执行中不隐式切换。

# OpenAI 的独立 Exec 尚未在所列研究资料中确认，故不提供执行配置。
适配器 options固定语义
podman/v1cli_ref、deployment_ref、正整数 request_timeout_seconds。deployment_ref 固定 rootless store/config/runtime、环境摘要、受信入口、挂载策略、网络和配额。
cloudflare-sandbox/v1api_ref、deployment_ref、正整数 request_timeout_seconds。deployment_ref 固定官方 bridge 源码/包/镜像组合、账户与 Worker、认证引用和内容保留；不能把某个普通 Worker URL 当作通用沙箱 API。
e2b/v1sdk_ref、deployment_ref、正整数 request_timeout_seconds。deployment_ref 固定账户／项目、模板、联网规则、TTL、SDK/envd 与内容保留要求。
共同私有 options 保存到 options_json；原生资源身份和实际 capability 保存在 Allocation。客户端 deadline 与任务 timeout 分别处理。未知必需字段或无法满足的语义在派发前拒绝。

能力归属与组合发布

Loom 拥有持续工作的受理、进度、等待、操作托管、内容接管、授权与恢复；模型访问由 Model Resource Hub 维护，受约束任务执行由 OnDemand Sandbox 维护，参考 Worksurface Harness 独立维护策略、循环、模板和测试。每项能力的实现、专用契约、依赖、部署与验证随所属仓库维护。公开消费者绑定留在调用方，不能跨仓库读写私有状态。

Harness 驱动请求单次模型操作；Runtime 先保存派发责任，通过模型能力取得原生结果并持久保存，再向驱动交付。模型访问不执行工具、不决定继续策略。任务执行返回已验证的执行路径与原资源身份；Runtime 不推断供应商挂载位置，必要结果未接管时保持原责任。

组合通过固定版本的公开包与源码依赖构建，独立获取 Loom 后也能按声明取得依赖。正常模型／工具循环、调用结果未知、文件交付失败、恢复原绑定和独立安装必须分别验证。参考组合的目标 API 由本书定义；当前迁移范围另记于源码仓库的 docs/capability-migration.md，该记录不随 HTML 规格包交付。

契约 版本／范围
Work 配置 T 使用 work.toml 结构 3、TOML 1.0。
受信 RPC／Durable DTO loom/2、loom.durable/1；JSON-RPC 2.0 封装。
事件传输信封 loom.event/1；作者 publish／subscribe／inputs 接口为本文目标 API，实际发布前须完成 DTO 与错误契约检查。
执行适配 sandbox.provider/2、tool.exec/1、sandbox.exec/1。
资源与内容访问 userspace.binding/1、workspace.access/1。
只读事实视图 facts.view/2；格式、来源游标、授权范围和覆盖说明。
上下文反馈 context.feedback/1。
独立模型／预算 model.invoke/1、budget.scope/1 草案；发布时须明确与旧 modelInvoke 载荷的迁移关系。

发布记录须固定源码、SDK、运行时、schema、数据转换器和环境摘要，并关联相应验证报告。不支持的主版本或必需能力须明确拒绝；新增可选字段只有在省略时行为明确且保持兼容，才能按兼容变更发布。
