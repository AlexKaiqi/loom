A.5 组件拼接与宿主配置

本页面向 Runtime 实现者与部署者，将公开逻辑资源解析为一套固定、获准并经过验证的实际组合。作者配置见第 8 章；事件、持久控制和 Harness 执行分别由前面的实现篇说明。此处维护服务位置、选件与版本、Profile 解析和组合启用要求。

公开 work.toml 示例已移至初始 Work 配置。它声明要使用什么逻辑资源，不包含 Worker、物理路径、引擎连接或管理凭据。

从逻辑声明到可用组合

待解析声明宿主必须确定对应实现
Runtime 与事件服务受信服务身份、事件存储与桥的部署、目标控制入口和兼容消息格式。事件与输入
Work 持久控制组合确定引擎、持久存储、原生 SDK／Worker 版本、作者形式和输入／Operation 接合。持久执行
Harness 逻辑环境代码装载与工具链、受管 SDK 通道、隔离设施、资源策略以及与控制组合的兼容绑定。执行管理
模型服务、Target 与 Userspace实际服务、模型／工具能力、资源范围、内容交付、原对象查询、停止和凭据注入方式。模型操作、Sandbox 调用接合

所有 @locked 引用先解析为确定摘要或固定部署身份。未解析、必需能力缺失、组合不相容或尚未通过故障轨迹验收时保持 not_ready，不接受新的业务调用。实际绑定由首次受理记录保护；升级配置不覆盖原运行，旧组合的内容、结果核对和恢复仍须可用。启用条件见统一验收。

Harness 环境与控制组合

下面是宿主私有配置的目标形状：逻辑 Harness 环境连接运行时、SDK、控制组合与资源策略；不同组合分别声明所支持的作者形式。首个运行设施及权限、装载、等待释放和重建机制由执行管理维护，R／T 接合由持久执行实现维护。

# 宿主私有配置的目标形状；所有引用解析为确定摘要后才能受理调用。
[harness_environments.harness-js]
runtime_profile = "runtime:linux-node@locked"
sdk_ref = "sdk:loom-harness@locked"
binding_ref = "durable-binding:primary@locked"
policy_ref = "policy:harness-call-scope@locked"
max_parallel_calls = 8
max_depth = 16

# 优先验证动态受管顺序代码；未通过接合验收时不得标成 ready。
[durable_bindings.primary]
engine = "resonate"
engine_ref = "engine:resonate@locked"
sdk_ref = "sdk:resonate-ts-async@locked"
loader_ref = "loader:immutable-harness@locked"
transport_ref = "transport:scoped-sdk@locked"
service = "primary-durable"

# Temporal 预装代码的专用部署形状，不属于公开 work.toml。
[durable_bindings.temporal-preloaded]
engine = "temporal"
mode = "preloaded_workflow"
workflow_type = "basicHarness"
workflow_bundle_ref = "bundle:basic-workflow@locked"
worker_ref = "worker:temporal@locked"
task_queue = "loom-approved-workflows"

# 动态显式状态：固定 Workflow，候选代码在隔离 Activity 内有限推进。
[durable_bindings.temporal-dynamic-state]
engine = "temporal"
mode = "explicit_state"
workflow_type = "genericWorkWorkflow"
workflow_bundle_ref = "bundle:generic-workflow@locked"
advance_worker_ref = "worker:linux-node-advance@locked"
task_queue = "loom-dynamic-state"

创建 Work 时由初始入口与宿主策略固定一套控制组合；三个 binding 是不同 Work 的可选接法。每次启动保存解析后的实际 HarnessBinding，并核对作者形式与 Work 控制组合相容。policy_ref 只引用受信策略；调用范围、名额与深度按契约执行，候选代码不能修改这些宿主配置。

Sandbox 的消费绑定

Target 的公开配置见第 8 章。宿主将逻辑 Target 接到获准 Sandbox 服务和公开契约；实际后端、镜像、原生身份、SDK 和私有 options 由 Sandbox 管理，Loom 不另维护它们的模式。

# Loom 宿主消费配置的目标形状；不定义供应商 options。
[services.primary-sandbox]
capability = "ondemand-sandbox"
interface = "task-executor"
contract_ref = "contract:sandbox-task-execution@locked"
binding_ref = "sandbox-binding:approved-executor@locked"

[profiles.local-default]
service = "primary-sandbox"
requirements_ref = "requirements:command-and-stable-files@locked"

TaskExecutor 的固定公开 Binding 由 Sandbox 部署或受信装配取得，包含实际非秘密目的地与配置。Loom 保存该 Binding 及必要公开检查点，恢复时回到同一公开 Query／Cancel／Release 入口；不从工厂导入供应商 SDK，不推断文件路径，也不按最新 Profile 换后端。凭据通过受信部署注入，任务环境不取得管理身份。

原后端配置设计归 Sandbox 的 docs/backend-configuration.md。调用者只声明要求和许可范围；实际隔离、稳定文件及资源释放由 Sandbox 完整兑现。组合必须固定公开契约版本、调用组件与 Sandbox 实际部署，能力不足或未验证时保持 not_ready。

能力归属与组合版本

Loom 拥有持续工作的受理、Harness 调用、固定代码装载、进度、等待、操作托管、内容接管、授权与恢复；模型访问由 Model Resource Hub 维护，受约束任务执行由 OnDemand Sandbox 维护，参考 Worksurface Harness 独立维护策略、循环、模板和测试。graph 维护通用图操作与展示，Harness 定义并校验图中关系、结构和状态的含义。每项能力的实现、专用契约、依赖、部署与验证随所属仓库维护。公开消费者绑定留在调用方，不能跨仓库读写私有状态。

各能力通过已声明的公开接口接合。单次模型／工具结果怎样进入控制组合见操作拼接；环境后端的请求、内容与原对象核对见Sandbox 调用接合。适配器的私有变化由所属能力吸收，公开契约变化则更新受影响的消费者和组合验证。

组合通过固定版本的公开包与源码依赖构建，独立获取 Loom 后也能按声明取得依赖。正常模型／工具循环、调用结果未知、文件交付失败、恢复原绑定和独立安装必须分别验证。参考组合的目标 API 与验收由本书定义；实现和重构计划另由所属仓库维护，不能反向降低这些要求。

契约 版本／范围
Work 配置 work.toml 结构 4、TOML 1.0；宿主引擎绑定格式由对应适配器定义。
受信 RPC／Durable DTO loom/2、loom.durable/1；跨进程参考封装见SDK 通信。
事件传输信封 loom.event/1；作者 publish／subscribe／inputs 接口由事件契约定义，实际发布前须完成 DTO 与错误契约检查。
执行适配 tool.exec/1 与 Sandbox 消费接合；独立执行接口、后端模式和版本由 Sandbox 维护。
资源与内容访问 userspace.binding/1、workspace.access/1。
只读事实视图 facts.view/2；格式、来源游标、授权范围和覆盖说明。
上下文反馈 context.feedback/1。
Harness 调用／图发布 harness.call/1、loom.graph/1 目标契约；图内部快照复用 graph 版本 1，发布使用既有内容与事件契约。
独立模型／预算 model.invoke/1、budget.scope/1 草案；发布时须明确与旧 modelInvoke 载荷的迁移关系。

发布记录须固定源码、SDK、运行时、schema、数据转换器和环境摘要，并关联相应验证报告。不支持的主版本或必需能力须明确拒绝；新增可选字段只有在省略时行为明确且保持兼容，才能按兼容变更发布。
