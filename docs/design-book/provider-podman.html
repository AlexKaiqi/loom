接入前先核对 Provider 公共契约与任务执行契约。

rootless Podman CLI

rootless Podman 用于在 Linux 上提供独立任务环境。适配器调用现有 CLI，使用部署所选普通用户的 rootless 存储；原对象 ID 与存储身份一起保存。podman exec 可以复用活跃环境，镜像不是模型工具参数。[S35]

Loom 阶段具体 Podman 调用适配约束
Describe / 预检podman version --format json、podman info --format json记录 CLI/runtime/storage/cgroup 组合与 rootless 实况；检测 namespace、授权挂载和依赖；不因命令退出 0 自动宣称全部能力。
Acquirepodman create --name <原名> --label ... --network none --cap-drop ALL --security-opt no-new-privileges --mount ... <确定环境> <受信入口>；再 podman start <ID>实例名称由 Runtime 稳定生成，create 是独立 Effect。工作命令在其自身 Effect 派发屏障之后才执行；初始化入口不得提前执行用户脚本。配置只使用锁定且验证过的选项。
Executepodman exec --workdir <path> <原ID> <argv...>使用 os/exec 字面参数，按需 -i，不分配混流 TTY。125/126/127 的工具/调用错误与任务退出分开；transport/wrapper/task 的归因按真实证据。
InspectAllocation / 诊断podman container inspect <ID>；podman logs <ID>inspect 默认结构化输出。container logs 不是每次 exec 的完整输出库；task 输出由 Runtime 及时落 records。只读核对不调用 start。
Stop / Releasepodman stop <原ID> → inspect；内容和诊断受保护后 podman rm <原ID>整环境停止只用于已授权的独占分配；没有命令级能力就不声称 exec.stop。不得 --all、system prune 或删除业务卷。
shared 内容授权 bind mount + 宿主稳定捕获不调用 upload/download，不使用 rootfs export 冒充挂载内容快照。不要自动 chown 整个 Userspace；不要默认使用会改属主的 :U 或改变 SELinux 标签的 :z/:Z，确有需要须单独授权并验证。

本机接入清理 CONTAINER_HOST、CONTAINER_CONNECTION 及隐含远端配置，并固定受信 containers.conf、storage 和 runtime。可写范围排除 Runtime 数据、管理 socket、运行时配置及其他 Work 副本。命令结果重取、跨重启身份和停止范围按锁定版本的实际能力报告。
